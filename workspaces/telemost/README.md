# Яндекс Телемост

Окружение открывает ссылку в отдельном Chromium и входит гостем под именем «ГЛаДОС».
Из диалога можно попросить «ГЛаДОС, подключись к созвону в Телемосте» и приложить
ссылку. В дашборде откройте окружение «Яндекс Телемост», вставьте ссылку и нажмите
«Подключиться». Для выхода используйте кнопку «Отключиться» или попросите агента
выйти. Один экземпляр окружения ведёт один звонок одновременно.

У гостя должны быть права на вход по ссылке. Если встреча требует допуска,
панель покажет ожидание и даст организатору время принять гостя. Для браузерного
входа не нужны ключи Яндекса, SIP-коннектор или сессия личного браузера.

## Запуск

В образ входят Chromium, Playwright, PulseAudio и локальная модель для голосовых
меток. Сборка из корня GitS: `docker build -f docker/core/Dockerfile -t gits-core:dev .`

При запуске вне Docker нужен Linux с Chromium, PulseAudio, pactl, parec
и pacat, а также Python-пакеты Playwright и sherpa-onnx. Путь к Chromium можно
передать в `GITS_TELEMOST_CHROMIUM`. Путь к модели для ядра задаётся
через `GITS_TELEMOST_DIARIZATION_MODEL`.
[Модель WeSpeaker ResNet34](https://github.com/k2-fsa/sherpa-onnx/releases/download/speaker-recongition-models/wespeaker_en_voxceleb_resnet34.onnx)

## Кто говорит

Браузер передаёт смешанный звук. Для каждой подходящей фразы голосовой движок
локально извлекает голосовой эмбеддинг и сопоставляет его с уже найденными
говорящими в этой сессии. Метки «Спикер 1», «Спикер 2» появляются в событиях
и голосовой расшифровке. Номера действуют только в сессии, голосовые эмбеддинги
хранятся в памяти процесса. Короткие и неоднозначные фразы остаются без номера.
Если модель недоступна, распознавание речи продолжается с общей меткой
«Участники Телемоста». Метод не разделяет одновременную речь и не определяет
имена участников.
