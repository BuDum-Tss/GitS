# Адаптер голоса «виртуальные кабели» (`adapter="cable"`)

Зачем: ГЛаДОС участвует в звонке, который идёт в стороннем клиенте (Discord, Telegram, Zoom и т. п.), без бота и без доступа к API
программы. Программа работает со звуком через обычные устройства, а мы подставляем вместо них два виртуальных кабеля (например,
VB-Audio Cable A и B) и подключаемся к движку голоса ядра (`docs/VOICE_ENGINE.md`).

## Схема

```
 собеседники ──► программа звонка ──(вывод)──► [CABLE-A Input]──кабель A──[CABLE-A Output] ──► адаптер ──► движок голоса
                                                                                                               │
 собеседники ◄── программа звонка ◄─(микрофон)─ [CABLE-B Output]──кабель B──[CABLE-B Input] ◄── адаптер ◄──────┘
                                                                                              (её голос)
```

Её голос в звук собеседников не попадает (другой кабель), поэтому адаптер объявляет `echo_free=True` и `can_barge_in=True`.
Все собеседники приходят смешанными: один «говорящий» `call` (`speakers_labelled=False`).

## Настройка программы звонка

1. Вывод звука (динамики) программы: `CABLE-A Input`.
2. Микрофон программы: `CABLE-B Output`.
3. Вход и выход адаптера: вход `CABLE-A Output` (читаем), выход `CABLE-B Input` (играем).
4. Собственный голос и звук системы не должны идти на кабель A, иначе она будет слышать лишнее.

Адаптер отказывается запускаться, если вход и выход это один кабель или одно устройство (петля: она услышала бы сама себя).

## Запуск

```
pip install -r services/audio_cable/requirements.txt
python services/audio_cable/main.py --list
python services/audio_cable/main.py --input "CABLE-A Output" --output "CABLE-B Input" --name "Маша" --owner
```

Параметры: `--input` и `--output` (подстрока имени без учёта регистра; неоднозначная подстрока даёт ошибку со списком),
`--session` (по умолчанию `cable`), `--name` (имя собеседника в событиях), `--owner` (говорящий считается владельцем), `--title`.
Остановка: Ctrl+C.

Переменные окружения: `GITS_CABLE_IN`, `GITS_CABLE_OUT` (вместо `--input`, `--output`), `GITS_TOKEN` (токен шины), `GITS_VOICE_URL`
или `GITS_CORE_URL` (адрес движка), `GITS_SECRETS_FILE` (путь к `.env`, по умолчанию `.env` в корне репозитория). Токен не печатается.
Звук не пишется на диск и не попадает в журнал, только счётчики (раз в минуту строкой INFO).

## Требования

`soundcard`, `numpy`, `aiohttp`, `python-dotenv` (`requirements.txt`), Python 3.12+. Виртуальные кабели ставятся отдельно (VB-Audio и т. п.).

## Тесты

`python -m pytest services/audio_cable/tests -q -p no:cacheprovider`: поиск устройств, проверка петли, буфер выхода и адаптер против настоящего
движка в процессе (`FakeStt`, `FakeTts`, `MemoryIn`, `MemoryOut`).

## Что проверено, что нет

Проверено тестами: сопоставление имён и петля, буфер выхода (мгновенный abort, тишина при паузе, счёт сыгранного), сквозной ход через
настоящий движок (речь доходит событием, реплика играется в 48 кГц стерео нужной длины, `play.stop` и перебивание обрывают за пару
кадров, переподключение восстанавливает говорящего). Не проверено: живые устройства. На этом ПК виртуальных кабелей нет, поэтому
`SoundcardIn` и `SoundcardOut` не открывались ни разу (только `--list` перечисляет устройства); задержка, дрейф частот между кабелями
и поведение программы звонка проверяются на первом настоящем запуске.
