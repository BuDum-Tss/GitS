# GitS: ГЛаДОС, ассистентка на компьютере

Всегда включённый ассистент с характером из папки персонажа (сейчас ГЛаДОС): разговор, зрение (экран), голос и слух, управление
компьютером, память-эпизоды, собственные размышления и напоминания, Telegram, игры, питомец на рабочем столе. Всё на Python 3.12+,
ввод-вывод асинхронный (`asyncio`). Локальная модель (LM Studio) отвечает за быстрые реплики и разбор намерений, Claude Code SDK
берёт тяжёлые задачи. Она не болтает по таймеру: говорит в ответ на события, на просьбы и на напоминания, которые назначила себе.

## Как это устроено

**Ядро** (`agent/`) принимает события от источников, решает, что с ними делать, говорит и помнит. **Окружения и сервисы** (участники шины; их код лежит в `workspaces/` и `services/`) это
отдельные процессы, которые подключаются к ядру по WebSocket (`ws://127.0.0.1:8766/ws`) и общаются
только по контракту; ядро само запускает их по `agent/peers.yaml` (разделы `workspaces:` и `services:`).

Ядро разрезано на слои (ТЗ 29, чистая архитектура):

| Слой | Где | Что внутри |
|---|---|---|
| Домен | `agent/domain/` | чистые функции решений без ввода-вывода: приоритет и свежесть, правила («замолчи», «похоже на просьбу»), риск, политика фокуса, лимиты импульсов, `Event` |
| Сценарии | `agent/app/` | нормализация события, оценка, диспетчер (маршруты `say`, `chat`, `task`, `focus`, `think`, `digest`), разговор, контекст, ответ, запоминание, размышление, таймер импульсов |
| Адаптеры | `agent/adapters/` | локальная модель, SQLite-журнал, личная память, люди, настройки, разрешения, файлы напоминаний и мыслей |
| Контракты | `agent/interfaces/contracts.py` | интерфейсы между сценариями и адаптерами (`LanguageModel`, `MemoryReader`, `MemoryWriter`, `PeopleDirectory`, `EventLog`, ...) |
| Корень сборки | `agent/core_service.py`, `agent/main.py` | собирает всё вместе, запускает слои |

Путь события: источник (участник шины или чат дашборда) -> шина участников шины (`module_hub.py`) -> менеджер внимания (`attention.py`: правила,
классификатор GLiNER, приоритет, решение D0-D4, маршруты) -> разговор / планировщик инструментов (`services/tools/router.py`) / менеджер фокуса
(`focus.py`) / сводка / размышление (`services/reflection/reflection.py`). Речь идёт только через очередь речи внимания (`speech_queue.py`) и не
при «не отвлекать». Внутренние импульсы: сама назначенная отметка («напомни себе через час», план пользователя со сроком, разговор
затих) становится событием `self.*` и попадает в то же размышление; мысли пишутся в журнал и не озвучиваются.

Память из двух частей: эпизоды (`episodes.db`: жизнь, канон из `memories.yaml`, заметки «запомни»; текст от первого лица, отдельных профилей и фактов нет) и цели с планами (задачи `tasks.db`),
гибридный поиск (`agent/services/memory_service/search/`), воспоминания персонажа о себе. Эмоции (ТЗ 26) и настроение влияют на тон.

Схему архитектуры (группы, компоненты, связи, статусы «есть/планируется») показывает вкладка **«Схема»** дашборда
(`http://localhost:8766`). Источник схемы: `tools/architecture/spec.py`, сборка: `python -m tools.architecture.build`
(тест `test/test_architecture_spec.py` следит, чтобы собранное совпадало с источником).

## Участники шины

| Участник шины | Папка | Что делает |
|---|---|---|
| Голос | `services/voice` | микрофон и распознавание (GigaAM на процессоре, запасной faster-whisper), синтез (Fish Speech, запасной edge-tts), воспроизведение, слух системного звука |
| Питомец | `services/pet` | окно на рабочем столе: стикер и облачко по состоянию (`presence`) |
| Компьютер | `workspaces/desktop` | зрение и экран, мышь и клавиатура, приложения, Участник шины кода как задача |
| Telegram | `workspaces/telegram` | канал-дневник, бот, её собственный аккаунт |
| RimWorld | `workspaces/rimworld` | мод, MCP-сервер, игровые контуры, комментатор |
| Монтаж | `workspaces/montage` | конвейер роликов (Remotion, ffmpeg, агент pi) |

Включаются во вкладках «Окружения» и «Сервисы» дашборда (там же настройки, задачи и вопросы участников шины). Профили поведения: `agent/profiles/*.yaml`.
Игровые и прочие специальные вещи живут только в своём участнике шины, в ядре их нет.

### Контракты и новый участник шины
- **Контракт «ядро - участник шины»** описан в одном месте, `agent/interfaces/workspace/gits_sdk/contract/` (запросы, сообщения, темы, окружение, версии). Из него
  скриптом `python agent/interfaces/workspace/tools/gen_contract_doc.py` строятся [docs/MODULE_CONTRACT.md](docs/MODULE_CONTRACT.md) и схемы `docs/contract/*.json`
  (тест сверяет). Запросы участника шины к ядру: `core.ask`, `core.tts`, `core.tool.call`, `core.persona`, `core.llm.ask`,
  `core.memory.recall` / `core.memory.remember` и другие.
- **SDK** (`agent/interfaces/workspace/`, пакет `gits-sdk`): типизированные `WorkspaceClient` и `ServiceClient`, `FakeCore` для тестов без ядра. Ядро берёт SDK напрямую из репозитория
  (`agent/main.py` добавляет `sdk` в `sys.path`), ставить его не нужно; для участника шины в своём окружении: `pip install -e sdk`.
- **Шаблон нового участника шины**: [agent/interfaces/workspace/template/](agent/interfaces/workspace/template/README.md) (манифест, обработчики, точка входа, тесты на `FakeCore`);
  пример с задачей, прогрессом и вопросом пользователю: `agent/interfaces/workspace/examples/echo_module.py` (выключен по умолчанию).
  Руководство автора: [docs/MODULES.md](docs/MODULES.md). Участники шины не импортируют файлы `agent/` (тест это ловит).

## Запуск
```powershell
cd agent
pip install -r requirements.txt -r ../services/voice/requirements.txt    # ядро и звук
copy .env.example .env     # токены Telegram и т.д. (не в git)
python main.py                           # ядро и дашборд на http://localhost:8766; участники шины запускает само ядро
pythonw clients/tray/tray.py                          # трей: поднимает только ядро
```
- Внешние сервисы (необязательные): `docker compose up -d` поднимает синтез голоса (ESpeech, запасной Fish Speech; память-граф Docker не нужен). Локальная модель:
  LM Studio (`google/gemma-4-e4b` и эмбеддинги EmbeddingGemma). Классификатор внимания GLiNER: `services/decider/README.md`.
- Без Fish Speech участник шины голоса говорит запасным edge-tts (нужен интернет); микрофон всегда распознаёт локально (GigaAM, запасной faster-whisper;
  веса скачивает владелец сам, речь двух людей не различается). Если голос выключен, она отвечает текстом в чате дашборда.
- Без звука и без окна для проверки запуска: `GITS_VOICE_FAKE=1`, `GITS_PET_HEADLESS=1`. Выключить второй эшелон фокуса: `GITS_FOCUS_LLM=0`.
- Вручную (при разработке, ядро должно работать): `python services/voice/main.py`, `python services/pet/main.py`.
- Telegram: токен бота и канал (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL`) и ключи аккаунта (`TELEGRAM_API_ID`, `TELEGRAM_API_HASH`) лежат
  в `.env`; вход в аккаунт один раз вручную: `python workspaces/telegram/tg_login.py`.

## Персонажи
Персонаж (ГЛаДОС сейчас) это данные, а не код: папка `resources/<Имя>/` с `core/character.yaml` (карточка), `core/` (промпты и воспоминания ядра)
и по папке на участник шины (`voice/`, `pet/`, `telegram/`, `desktop/`, `rimworld/`, `montage/`). Участник шины берёт ресурсы только из своей папки
(`gits_sdk.resources.module_dir("pet")`). Память у каждого персонажа своя (`memory/` для `glados`, `memory/characters/<id>/` для остальных).

Как добавить персонажа:
1. Скопировать `resources/_template/` в `resources/<Имя>/` (id в `core/character.yaml`: строчные латинские буквы, цифры, `_`).
2. Заполнить `core/character.yaml`: `id`, `name`, `aliases`, `anchor` (до 600 символов), `voice`.
3. Написать `core/prompt.yaml` и `<участник шины>/persona.yaml`. `core/character.yaml` (карточка и конституция) меняет только человек.
4. Воспоминания: `core/memories.yaml`, загрузка в канон эпизодов (ядро делает это само при открытии памяти; вручную `python -m services.memory_service.character_seed seed <id>`, `--dry-run` только проверяет файл).
5. Переключение: дашборд (`POST /api/character`) или инструмент `core.set_character`.

## Характер, память и учёба
Эмоции (валентность, возбуждение, настроение с затуханием к базовому уровню персонажа), эпизоды с резюме от первого лица и режим сна с дневником (`memory/episodes.db`), уроки на ошибках и убеждения, которые она принимает сама с журналом изменений и отменой в дашборде (ТЗ 26-28). Поиск по памяти гибридный (`agent/services/memory_service/search/`: слова и векторы). Конституция меняется только человеком.

## Быстрый контур
Реплика идёт по понятным маршрутам (`reflex`, `chat`, `task`, `ignore`, `think`): жёсткие правила
до моделей («замолчи» и другое, `agent/services/tools/hard_rules.yaml`), затем реплика уходит единому агенту (одна постоянная сессия Claude,
`agent/app/resident.py`): он сам ищет и вызывает инструменты, а его текст звучит по мере появления; «замолчи» и перебивание
обрывают ход. Поиск в памяти идёт с дедлайном 300 мс. Настройка `latency_budget`.

## Устойчивость ядра
`python tools/soak_core.py --minutes 10` поднимает настоящее ядро без участников шины (модель и речь заглушены), шлёт реплики и события,
подключает и роняет фиктивные участники шины и раз в 10 секунд снимает память, задержку цикла событий, число задач, ошибки и очереди
(критерии и результаты: [docs/CORE_SOAK.md](docs/CORE_SOAK.md)); с `--real-modules telegram,voice,pet` то же с настоящими участниками шины в режиме
заглушек и убийством их процессов. Режим «только ядро»: настройка «Только ядро» в дашборде или `GITS_NO_MODULES=1`.

## Окружения и сервисы
Ядро принимает участников по WebSocket (`ws://127.0.0.1:8766/ws`, токен в `%LOCALAPPDATA%\GitS\module_token`) и само
запускает их по `agent/peers.yaml` (супервизор). Включаются и выключаются во вкладках «Окружения» (workspace; режим владения shared или
owned) и «Сервисы» (service, включая внешние decider и espeech) дашборда (там же настройки, задачи и вопросы). Профили поведения лежат в `agent/profiles/*.yaml`. Руководство автора участника шины: [docs/MODULES.md](docs/MODULES.md),
Первый тестовый участник шины, `echo` (`agent/interfaces/workspace/examples/echo_module.py`), выключен по умолчанию.

## Как проверять
```powershell
.\check.ps1       # ruff и все тесты: ядро, sdk, шаблон участника шины, telegram, voice, pet, desktop, rimworld, montage
```
По частям (из корня репозитория):
```
python -m ruff check agent sdk services modules
python -m pytest -q test agent/interfaces/workspace/tests            # ядро и SDK
python -m pytest -q agent/interfaces/workspace/template/tests               # шаблон участника шины
python -m pytest -q workspaces/telegram/tests           # то же для voice, pet, desktop; у каждого участника шины отдельный запуск
```
Тесты не ходят в сеть, к микрофону, игре и подписке: модель и внешние службы заменены заглушками. Тесты `rimworld` и `montage` запускай
из их папок с `PYTHONPATH=agent/interfaces/workspace`. После правки контракта запусти `python agent/interfaces/workspace/tools/gen_contract_doc.py`, после правки схемы
`python -m tools.architecture.build` .
