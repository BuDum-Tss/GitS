# Объявления о долгих запусках в модуле RimWorld (аудит, правило 14)

Правило 14 README GitS (решение владельца 2026-10-11): каждый долгий или заметный запуск программы или инструмента на ПК
озвучивает персонаж. Модуль передаёт факт «что делается и зачем», фразу строит модель. Быстрые вспомогательные операции
(поиск, конвертация, короткий ffmpeg, внутренние процессы) не озвучиваются. Аудит по коду ветки `tz/16-announce-audit`.

Путь объявления в модуле: `game_launcher.announce_fact` → уведомитель процесса модуля (`core_link.announce`:
`client.say(mode="fact", announce=True)`); из скриптов и тестов без уведомителя - `POST /api/notify` дашборда ядра
(тихо, если ядра нет). Заметные действия модуля идут через `game_launcher.announce_self(fact, kind)`: факт получает
пометку «не пользователь» (как DP-2 у запуска игры). В тестах `conftest.py` подменяет оба вызова списком
`game_launcher.announced`.

| Запуск | Объявляется | Как | Почему |
|---|---|---|---|
| Запуск игры: `game_launcher.launch(reason)` (в т.ч. сторож «игра не запущена», автозапуск `GITS_LAUNCH_GAME`) | да (уже было) | `announce(reason)` до запуска | долгий запуск, reason обязателен |
| Сторож запускает игру снова (`launch_game`) | да | через `launch(reason)` (тот же путь) | это запуск игры |
| Нажатие «Быстрый запуск» в главном меню, создание поселения (`Controller._new_colony`, кнопка найдена) | **было нет, добавлено** | `announce_self`, `kind="game"` | игра стартует новую партию |
| Навигация по меню через Claude по экрану (`Controller._navigate_to_game`: после неудачной кнопки, при гибели колонии) | **было нет, добавлено** | `announce_self`, `kind="game"`, в факте цель (до 160 символов) | долгий, до 90 с, Claude ведёт игру |
| Меню без Claude: OCR-клик «Быстрый запуск»/«Продолжить» (`_menu_autostart`) | да, через ядро | инструмент `desktop.menu_click` с флагом `announce` (GitS, ветка `tz/16-announce-audit`) | клик идёт через `POST /api/menu_click` ядра; второе объявление здесь не добавлено, чтобы не дублировать |
| Старт записи забега или следующего куска (`RunRecorder.start`: ffmpeg окна и звук) | **было нет, добавлено** | `announce_self`, `kind="video"`; в факте колония, звук (есть/нет) и причина `why` | долгий ffmpeg, заметен пользователю |
| Перезапуск записи из-за смерти ffmpeg или предела длины (`ensure_alive`) | **было нет, добавлено** | тот же вызов `start` с причиной `why` | это старт записи; одно объявление на кусок |
| Бот перезапустился посреди забега (`Controller`, `recorder.start` в продолжении забега) | **было нет, добавлено** | тот же вызов с причиной `why` | продолжение записи того же забега |
| Монтаж и клипы (`RunRecorder.process`: конец забега, перезапуск куска, `tools/produce_run.py`) | **было нет, добавлено** | `announce_self`, `kind="video"` (только если есть что монтировать) | долгий рендер ffmpeg |
| Пустая или короткая запись (монтаж пропущен) | нет | - | ничего не запускается |
| Перезапуск звука (`restart_audio`, `ensure_audio`) | нет | - | внутренний кусок записи звука в той же записи, протокол пишет его сам (REC-2) |
| Показ окна игры (`show_window`, перевод окна на передний план) | нет | - | короткое действие; частоту ограничивает сторож (`FOCUS_COOLDOWN_S`) |
| Пауза и снятие паузы сторожем (GT-1, GT-2, пауза при пользователе) | да (уже было) | `_say` сторожа | это не запуск, но объявляется по GT-1, GT-2 |
| Закрытие игры | в коде модуля нет | - | модуль игру не закрывает |
| Скрипт `rebuild_and_launch.ps1`: закрывает и запускает игру | **было нет, добавлено** | `POST /api/notify` (тихо, если ядра нет) до закрытия игры | скрипт - тоже запуск, правило 14 велит объявлять из скриптов через `/api/notify` |
| Скрипт `diagnose.ps1` | нет | - | только читает состояние, ничего не запускает |
| `run_mcp.py` (внутренний процесс MCP-сервера) | нет | - | внутренний процесс |
| Инструменты MCP (`rimworld_mcp.py`) | нет | - | команды игре, не запуск программ |

## Открытые вопросы владельцу

1. Перезапуск звука (`restart_audio`) не объявляется: это кусок записи звука внутри той же записи, а не отдельный запуск.
2. `rebuild_and_launch.ps1` объявляет через `POST /api/notify` в ядро на `localhost:8766`; если ядро другое или его нет,
   объявления нет (тихо, как у всех скриптов).
3. `tools/produce_run.py` объявляет монтаж через HTTP на ядро, потому что уведомителя процесса модуля там нет.
