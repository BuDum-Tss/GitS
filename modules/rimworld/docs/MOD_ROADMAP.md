# Дорожная карта мода AgentBridge

Что нужно добавить в мод (C#, `mod/AgentBridge`) и в MCP-сервер (`agent/rimworld_mcp.py`), чтобы ГЛаДОС
могла развивать колонию, строить, торговать и воевать. Порядок: по волнам, каждая закрывается целиком
(мод + MCP-инструмент + строка в инструкции агента + проверка).

Правила для всех волн:
- Команда, которой мод не знает, возвращает `ERROR`, а не «OK».
- Команда сообщает, что реально произошло: что применилось и почему нет (а не просто «OK»).
- Всё, что она видит или делает, доступно через MCP-инструмент и описано в `glados_agent.py`.
- Мод собирается без остановки игры во временную папку (проверка компиляции); живой DLL обновляется,
  только когда игра закрыта: `dotnet build mod/AgentBridge/AgentBridge.csproj -c Release`.

## Волна 1. Бой

**Цель:** на нападение она реагирует сама, быстро и осмысленно: вооружает, одевает, ставит в бой, стреляет,
спасает раненых, берёт пленных, лечит, а после боя наводит порядок.

### Мод
| # | Что | Как |
|---|---|---|
| 1.1 | `capabilities` и честный `default` | Список команд мода; неизвестная команда даёт `ERROR: unknown command` |
| 1.2 | `get_items` (запрос) | Предметы на карте по категории (`weapon`, `apparel`, `medicine`, `food`): id, def, качество, количество, позиция, запрещён ли, дальнобойное ли, броня |
| 1.3 | `attack`: стрельба | Если у бойца дальнобойное оружие, приказ идёт через `AttackStatic` с нужным `verb`, иначе рукопашная |
| 1.4 | `equip`: через работу | Пешка сама идёт и берёт оружие (`JobDefOf.Equip`), без мгновенной вставки в руки |
| 1.5 | `wear` | Пешка идёт и надевает одежду или броню (`JobDefOf.Wear`) |
| 1.6 | `rescue` | Колонист несёт раненого колониста на свободную кровать |
| 1.7 | `capture` | Арест лежащего врага: несёт на кровать, становится пленным |
| 1.8 | `tend` | Назначить врача на раненого |
| 1.9 | `set_manual_priorities` | Включить «ручные приоритеты» (приоритеты 1–4 вместо вкл/выкл) |
| 1.10 | Больше данных о пешках | `is_downed`, `bleeding`, `wounds`, `incapable_of`, `weapon`, `weapon_ranged`, `apparel` |
| 1.11 | Больше данных о врагах | `kind` (человек, животное, механоид), `is_fleeing`, `is_ranged` (плюс `is_downed`, `job`, `weapon`) |
| 1.12 | События боя | `pawn_downed`, `enemy_downed`, `enemy_killed`, `incident` (начало рейда и тип) |
| 1.13 | `force_work`, `clear_work_queue` | Принудительный порядок работы как Shift+ПКМ: пешка делает работу на клетках по порядку (стройка, рубка, добыча, перевозка, верстак, лечение), работу подбирает игра через WorkGiver с forced=true |

### MCP и агент
- Инструменты: `get_items`, `wear_apparel`, `rescue_pawn`, `capture_pawn`, `tend_pawn`,
  `set_manual_priorities`; `attack_target` и `equip_item` обновлены.
- Инструкция: раздел «Тактика боя»: вооружить, одеть, поднять в бой, цели, раненые, пленные, отбой.
- Контроллер: «бой окончен» (враги были и пропали): отдельный ход: снять драфт, вылечить, собрать трофеи.

### Готово, когда
- Налёт: за один срочный ход бойцы вооружены, одеты, в бою; раненые спасены; враги лежат под арестом или добиты.
- «Бой окончен» запускает уборку без твоего участия.
- Проверка на живой игре после перезапуска (песочница с налётом через режим разработчика).

## Волна 2. Надёжность и настройки игры
- Структурные ответы команд: `{ok, applied, reason}` для всех действий, а не «OK».
- Политики одежды, еды и препаратов; разрешённые зоны для пешек.
- Сохранение игры, быстрый старт новой колонии без кликов по интерфейсу.
- Правка `StateSerializer`: комнаты (крыша, закрытость, красота, температура), кровати и их владельцы.

## Волна 3. Производство и стройка
- `get_recipes(workbench_id)`: что можно сделать на верстаке (конец угадывания названий).
- Параметры биллов: пауза, ингредиенты, до какого количества.
- Фильтры склада, выбор культуры для грядки, назначение кроватей.
- Электричество: генераторы, батареи, подключение; температура и охлаждение.

## Волна 4. Торговля
- `get_trade_state`: торговец, его товары с ценами, что можно продать.
- `sell`, `buy` у визитёра, орбитального торговца, каравана.
- Что продавать, а что держать: правила на стороне агента.

## Волна 5. Решения и события
- Письма с выбором: принять или отказать (квесты, «странник просится в колонию»).
- Пленные: вербовка, освобождение, допрос.
- Ideology: роли, ритуалы (похороны), мировоззрение.
- События: окончание исследования и постройки, срывы, голод, болезни.

## Курсор на таблицах (ветка fix/cursor-on-tables)

Симптом: агент меняет цифры приоритетов в окне «Работа», а розовый курсор «GLaDOS» стоит в стороне. Причина: `AutoCameraFor`
для команд из `RequiredTab` вёл курсор к фиксированной точке (42% ширины, 62% высоты). Сделано (`mod/AgentBridge/Source/Commands/TableCursor.cs`):
- курсор едет к ячейке: строка пешки, столбец работы (`set_work_priority`, `set_work_priorities` в Python шлёт по одной команде на работу),
  колонка медицинского ухода (`set_medical_care`), часы по ширине окна (`set_schedule`, `set_schedule_range`), для
  `set_manual_priorities` точка у переключателя над таблицей. Потом вспышка клика (`AiCursorClickUntil`), и только потом правка;
- положение: постфикс `PawnTable.PawnTableOnGUI` запоминает origin таблицы (UI-координаты); высоты строк и ширины колонок берутся из
  приватных кэшей таблицы (`cachedRowHeights`, `cachedColumnWidths`), прокрутка `scrollPosition`, шапка `HeaderHeight` (если поля нет,
  40 px); строка ищется в `PawnsListForReading`, столбец работы в `PawnTableDef.columns` по `WorkTypeDef` воркера колонки;
- ожидание: первый перелёт серии по скорости руки (`CursorGlide`, не дольше 3 с), соседние ячейки не дольше 0,6 с каждая, общий
  потолок серии 4 с (`TableGeometry.WaitFor`, чистая функция);
- без найденной таблицы: origin `(2%, 12%)` экрана, строка по порядку колонистов, столбец по порядку видимых работ.
- `set_manual_priorities` в моде только переключает флаг (одна точка, не список ячеек). Серия ячеек возникает в `set_work_priorities` (Python).

Ограничения (проверить в игре): точная геометрия зависит от того, что игра хранит в кэшах (имена полей найдены в `Assembly-CSharp.dll`
RimWorld 1.6, но их смысл не проверен запуском); колонки скрытые или прокрученные за экран не учитываются (курсор зажимается в экран,
число меняется всё равно); расписание не `PawnTable`, часы приближённо делят ширину окна; первый перелёт серии может быть до 3 с.
Нет тестов C#: положение проверяется глазами в игре.

Как проверить визуально (живой DLL не трогался, нужна сборка и закрытая игра, см. ниже): открыть вкладку «Работа» (`open_game_tab("work")`),
дать команду смены приоритета через агента (например `set_work_priorities` для одного колониста). Курсор должен подъехать к строке этого
колониста и столбцу работы, вспыхнуть кликом, и только потом поменяется цифра. Для ухода: вкладка «Назначение», `set_medical_care`.
Для расписания: вкладка «Режим дня», `set_schedule_range`: курсор идёт к строке пешки и часам (приблизительно).

Обновление живой DLL: при закрытой игре `rebuild_and_launch.ps1` или копия из `%TEMP%\agentbridge_check\AgentBridge.dll` в папку мода.

### Камера следит за агентом (дополнение владельца)

Жалоба: камера должна всегда следить за действиями агента, а ею управляет владелец. Что сделано:
1. Пачки команд: раньше при очереди больше 2 команд показ пропускался. Теперь показ сжимается (`AutoCameraFor(..., compact)`:
   ожидание не больше 0,25 с, пауза после действия 0,1 с), камера плавно едет к месту каждой команды; наверстывания без показа нет.
2. Все действия двигают камеру: в `StageTypes` добавлены `look_at`, `forbid`, `unforbid`; `CellOfCommand` понимает `thing_id` и
   `workbench_id` (предмет, верстак: forbid, add_bill, cancel_bill). Окно-зависимые команды (`research`, `set_*`) ведут курсор к
   таблице (см. выше). Без места (`pause`, `resume`, `set_time_speed`, запросы) камера не двигается по замыслу.
3. Камера не отдаётся навсегда: `CameraDirector.Active` больше не равен «режим auto» (запись): режиссёр держит кадр только пока
   есть цель (команда агента, слежение, около 4-6 с), между действиями кадр у пользователя. `set_auto_camera` с
   `enabled=false` отказывает в обёртке `rimworld_mcp.py` (мод не вызывается); после каждой загрузки сохранения
   `AutoCamera` снова `true` и сбрасывается отметка пользователя (`GameFinalizeInitPatch`).
4. Ввод пользователя (`Camera/UserCamera.cs`): после каждого кадра мод помнит, где камеру оставил. Если между кадрами позиция
   сдвинулась больше чем на 0,6 клетки или размер кадра на 0,4 (WASD, края, колесо), это явное движение пользователя: цели агента
   сбрасываются, агент не двигает камеру `user_camera_override` (по умолчанию 5 с; команда мода `set_user_camera_override`
   {enabled, seconds}, диапазон 1-30 с). Мелкий дрейф во время действия агента не считается: цель перезаписывается каждый кадр.
   Harmony-патча для ввода нет (риск), только сравнение позиций. Python-настройка в общих настройках ядра (`settings.py`,
   `SHARED_SETTINGS`) не сделана: сейчас значение только в моде, по умолчанию включено.
## Волна 7. Исследования: закрытые постройки и рецепты (`unlock_for`)

Python-сторона готова (`agent/research_unlock.py`, `unlock_for`, проверки в `place_building` и `add_bill`), мод не менялся по
решению владельца (менять только если без этого нельзя). Без двух команд ниже цепочка видна только на один шаг (то, что уже
доступно сейчас), а рецепт нельзя связать с исследованием. Шаг в таком случае честно помечается заблокированным с причиной.

| # | Что нужно | Почему | Статус |
|---|---|---|---|

Python уже читает эту команду (`_research_catalog`), если мод её знает | Нужна команда мода (CommandExecutor, CostCommands), после сборки проверить в игре |
| 7.2 | Исследование рецепта: поле `research` (`RecipeDef.researchPrerequisite`) в `list_recipes` и команда описания рецепта | `add_bill` принимает закрытый рецепт молча (`AddBill` не проверяет `AvailableNow`). | 7.3 | Проверка, что `create_stockpile`, `create_grow_zone` и другие зоны не закрыты исследованием | В этом изменении не проверено: признака закрытия для зон нет | Посмотреть в игре (зона открыта без исследования, если в Core нет предпосылки) |
