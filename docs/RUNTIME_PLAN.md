# План работ: переход на каркас рантайма

Основа: `docs/RUNTIME_SPEC.md` (разделы и критерии приёмки оттуда). Статус: черновик плана, 18.11.2026.

## Исходное состояние (опорные места кода)

- Внимание: `agent/services/attention/` (`service.py` фасад `Attention`: `submit`, `submit_speech`, `submit_question`, `on_job_update`;
  `pipeline.py` правила R1-R6, `dispatcher.py` D0-D4, `digest.py`, `focus_stack.py`, `speech_queue.py`), классификатор `agent/services/classifier/`.
- Агент: `agent/services/conversation/resident.py` (`ResidentAgent`: `handle_user`, `handle_event`, `preempt`, `cancel`, `busy`, `_turn`),
  рантайм модели `agent/services/runtime/pi_runtime.py` (`PiRuntime`: `run`, `steer`, `abort`, `reset`), `pi_llm.py`.
- События модулей: SDK `agent/interfaces/workspace/gits_sdk/client.py` (`event(...)` с `urgency_hint`, `say(...)`), обработчики `agent/services/event_handlers/`.
- Журнал: `agent/services/tracing/events_log.py`, `journal.py`. Окружения: `agent/services/spaces/`, `agent/environments/`.
- Голос: `agent/services/voice_engine/` (события `voicechat.*`, инструменты `voice.*`).

Что именно меняется и во что, см. таблицу в `RUNTIME_SPEC.md` раздел 11.

## Принципы выполнения

1. **Старый и новый путь рядом.** Новое внимание включается флагом `GITS_ATTENTION=v2` (по умолчанию выключено) до конца этапа 5. Каждый
   этап оставляет ядро рабочим.
2. **Этап = одна проверяемая порция.** Тесты на заглушках (без модели, сети, звука), `ruff`, запись в `CHANGELOG.md`, при смене
   компонентов схема `tools/architecture/spec.py` (`python -m tools.architecture.build`).
3. **Роли.** Проектирование и приёмка: главная модель. Реализация по точным заданиям: субагенты Sonnet. Параллельные задачи получают
   непересекающиеся наборы файлов и отдельные ветки (разрешено правилами проекта); результат сводится в текущую ветку.
4. **Профильные тесты на каждом шаге, полный `check.ps1` один раз перед push** (правило проекта).
5. **Живая проверка** с ChatGPT и Pi Harness выполняется на этапах 3 и 6 вручную: пользователь запускает, мы смотрим журнал.

## Этап 2. Attention v2: process_event, on_turn, очередь (3-4 дня)

Зависит от этапа 1. Файлы: `attention_v2/queue.py` (приоритетная очередь, вытеснение, сводка), `attention_v2/attention.py` (`process_event`, `on_turn`,

## Этап 3. Runtime: ходы, журнал действий, прерывание (3-4 дня)

Зависит от этапа 0 (знание `PiRuntime`) и этапа 2 (интерфейс). Файлы: `agent/services/runtime/turns.py` (пачка -> промпт, журнал действий хода,
`interrupt`), правки `resident.py` (`busy`, `preempt`, `cancel` ложатся на новый контракт), признаки `effect`/`interruptible` в описании инструментов
(`agent/services/tools/`). Остановка речи при прерывании через `voice.stop` (позже `<ws>.stop`).

Готово: критерий приёмки 4; тест «прервано посреди хода с `say`» на заглушке модели; ручная проверка с живой моделью: фраза пользователя прерывает
долгий ход, агент получает блок «прервано».

Риск: поведение `steer` и `abort` в Pi Harness может не давать журнал вызовов; тогда журнал ведёт сам ядро по событиям вызовов инструментов.

## Этап 5. Адаптеры: TextAdapter и AudioAdapter (4-6 дней, параллельно по окружениям)

Зависит от этапов 1 и 4. Три независимые ветки (непересекающиеся файлы):

Готово: каждое окружение проходит свои тесты и тест «событие -> process_event -> строка для агента»; приоритеты соответствуют таблице раздела 3.2.

## Зависимости и параллельность

```
0 ──> 1 ──┬─> 2 ──> 3 ──┐
          ├─> 4 ────────┼─> 5a, 5b, 5c ──> 6
          └─────────────┘
```

Параллельно можно вести: этап 3 и этап 4 (разные файлы); 5a, 5b, 5c (разные окружения). Этап 2 и этап 1 не параллелятся: интерфейс события нужен очереди.
Оценка в сумме 18-25 рабочих дней исполнителя, из них критический путь 0-1-2-3-5-6 около 15-20.

## Риски

| Риск | Что делаем |
|---|---|
| `Pi Harness` не отдаёт журнал вызовов или не отменяется чисто | этап 0 проверяет; запасной путь: журнал по событиям инструментов в ядре |
| Приоритеты окружений выставлены «на глаз» и агент реагирует не так | таблица уровней единая, метрики по приоритетам, подбор констант на этапе 6 без правок кода (настройки) |
| Шторм прерываний или голодание фона | бюджет прерываний, `WAKE_MIN`, периодический `on_turn`, метрики |
| Регрессия голосового пути (задержка) | путь `USER` без очереди и пачки; сравнение `react_ms` до и после на этапах 5a и 6 |
| Контракт манифеста ломает старые модули | чтение старого манифеста с выводом видов из `urgency_hint`, пока не перенесены все окружения |
