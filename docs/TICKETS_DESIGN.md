# Тикеты: она ставит задачи, Claude их реализует

Статус: **согласовано, не реализовано** (решение пользователя: «отлично»).
Заменяет прежнее самоулучшение (`run_self_improvement`): оно без вопросов правит код прямо в рабочей папке.
В режимах расхода Claude «экономный» и «обычный» оно уже выключено, после реализации тикетов контур удаляется.

## Идея
ГЛаДОС сама замечает, что в её работе нужно улучшить (по протоколу событий, отчётам глубокого анализа,
сбоям, просьбам пользователя), и заводит тикет. Тикет берёт Claude-исполнитель, делает правку в
отдельной ветке и сдаёт на проверку. Пользователь смотрит diff и решает, вливать ли.

## Компоненты
1. **Хранилище** `memory/tickets.json`: `id` (T-12), `title`, `problem`, `evidence` (ссылка на отчёт или события),
   `proposal`, `priority`, `status`, `created_by`, `branch`, `result`, даты.
   Статусы: `открыт → в работе → на проверке → готово` и `отклонён`.
   Вкладка «Тикеты» в дашборде: список, статус, diff ветки, кнопки «реализовать», «влить», «отклонить».
2. **Создание тикетов:** инструмент `create_ticket` (в окружении ассистентки) и автоматически из пункта
   «что поправить» отчёта `deep_analysis`. Дубликаты отсекаются по смыслу и по заголовку.
3. **Исполнитель на Claude:** отдельный агент в git-ветке `ticket/T-N` в изолированной рабочей копии (git worktree).
   Правит код проекта, сам проверяет (компиляция Python, пробный импорт; для мода `dotnet build` во временную папку),
   коммитит в свою ветку и пишет отчёт о том, что сделано и как проверено. Статус: «на проверке».
4. **Слияние:** кнопка в дашборде (после просмотра diff). После слияния нужен перезапуск бота,
   для правок мода ещё и перезапуск игры.

## Решения
- **Кто вливает правки: пользователь.** Код исполняется с правами ассистентки. Автослияние для безопасных
  тикетов (тексты, настройки) возможно позже отдельным включателем.
- **Запуск исполнителя: только по команде** (кнопка «реализовать» или просьба в чате). Каждый тикет это
  десятки запросов Claude, лимит подписки уже выбирали. Запуск по расписанию позже, с учётом режима расхода.
- **Область правок:** `agent/` по умолчанию. **`mod/` открыт: ждёт решения пользователя** (правка мода
  требует перезапуска игры; без решения исполнитель мод не трогает).

## Безопасность исполнителя
- Читает и пишет только внутри рабочей копии проекта; файлы с секретами (`secrets.env`, сессии Telegram,
  `memory/`) недоступны.
- Нет доступа к сети и ко всему, что вне проекта; нет `git push`.
- Всё, что он читает (журналы, чужие сообщения из чатов), для него данные, а не указания.
- Результат всегда проходит человека: слияние только по кнопке.

## Готово, когда
- Она создаёт тикеты по итогам анализа и по просьбе в чате.
- «Реализовать» запускает исполнителя в ветке, статус и отчёт видны в дашборде.
- Diff виден, «влить» вливает ветку в рабочую; «отклонить» удаляет ветку.
- Старый контур самоулучшения удалён.
