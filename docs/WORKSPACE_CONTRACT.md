# Контракт рабочего окружения (workspace), версия 3.2, проект

Окружение (workspace) — рабочее место агента. Работает **сама ГЛаДОС** (резидентный агент), а не субагент-конвейер. Окружение
даёт ей инструменты, навыки, рабочую область, знания и сайт. Контракт общий для всех окружений: монтаж, RimWorld, помощник на ПК.
Дополняет `WORKSPACE_MODULES.md` (дерево узлов, панель, события) и `MODULE_CONTRACT.md` (шина, инструменты). Ломающих изменений нет:
новые поля идут в уже существующий блок `workspace` манифеста (рядом с `id`, `title`, `purpose`, `entry`) и необязательны, окружение без них работает как раньше.

## 1. Роли

| Кто | Что делает |
|---|---|
| ГЛаДОС (резидентный агент) | Понимает просьбу, читает навыки, вызывает инструменты окружения, правит файлы рабочей области, запускает долгие операции, зовёт пользователя на одобрение, озвучивает итог. Одна сессия, один характер, общая память. |
| Окружение (контейнер или процесс модуля) | Хранит рабочую область и ресурсы, даёт ей рабочее место и изолирует её контейнером, ведёт долгие операции, сообщает о ходе событиями, показывает сайт и панель. **Не запускает своих агентов.** |
| Ядро | Подключает окружение (аренда), показывает инструменты через `find_tools` / `call_tool`, проверяет риск, выдаёт внимание и очередь речи. |
| Пользователь | Одобряет необратимое и этапы, смотрит сайт окружения, видит в дашборде сводку и ссылку. |

## 2. Манифест: расширение блока `workspace`

```json
"workspace": {
  "id": "montage", "title": "Монтаж", "purpose": "...", "entry": ["user_message"],
  "brief": "Монтаж роликов: Remotion, ffmpeg, озвучка её голосом.",
  "skills": [{"name": "remotion-markup", "description": "...", "path": "skills/remotion-markup"}],
  "area": {"mode": "container", "root": "work", "hidden": ["node_modules", ".git"]},
  "commands": [{"id": "render", "title": "Рендер ролика", "background": true, "timeout_s": 3600},
               {"id": "still", "title": "Кадр", "timeout_s": 120}],
  "site": {"url": "http://127.0.0.1:8790/"}
}
```

- `brief` — вводная для агента (1–3 предложения): что за окружение. Подмешивается в контекст при входе.
- `skills` — справочные материалы окружения. Каждый навык — папка с `SKILL.md` внутри рабочей области или образа окружения. Агент читает навык по запросу, в контекст целиком он не попадает.
- `area` — режим рабочей области. `mode: "container"` (по умолчанию для окружений в своём контейнере): ограничений по путям нет, `root` — основная рабочая папка (точка отсчёта относительных путей), `hidden` — что не показывать в списках. `mode: "restricted"` (окружения без контейнера, на хосте): `writable`, `readonly` и `hidden` ограничивают пути, правила проверяет окружение.
- `commands` — исчерпывающий список разрешённых действий запуска. Произвольной оболочки нет. `background: true` — действие долгое и идёт как `job`.
- `site` — адрес сайта окружения (только чтение для человека).

## 3. Стандартные инструменты workspace

Имена одинаковы у всех окружений. Окружение объявляет их в `tools` манифеста как обычные инструменты (шина и `find_tools` те же).

| Инструмент | Что делает | Риск |
|---|---|---|
| `skills` | Без параметров — список навыков; `name` — текст навыка; `name` + `file` — файл внутри навыка | auto |
| `files` | `op`: `list`, `read`, `write`, `replace` (точная замена строки), `delete`, `move`; `path` в `area` | auto внутри `writable`, ask для `delete` |
| `resources` | Ресурсы персонажа и окружения: шрифты, звуки, дизайн, шаблоны (список или файл) | auto |
| `run` | `command` из `commands`, `args`. `background` → возвращает `job_id` и сразу | auto, ask для действий с пометкой `irreversible` |
| `work` | Рабочие единицы окружения (для монтажа — ролик): `create`, `list`, `status`, `cancel` | auto |
| `site` | Адрес сайта и страницы объекта (для ссылки пользователю) | auto |

Окружение вправе добавлять собственные инструменты (`resources`, `open_studio` и т. п.), но минимум для окружения с рабочей областью — таблица выше.

Ответы: `{"ok": true, "result": ...}` или `ToolError(code, message)` с кодами `denied` (вне `area`/`commands`), `unknown`, `busy`, `unavailable`, `invalid`. Большие файлы возвращаются обрезанными (по умолчанию 32 КБ) с признаком `truncated` и `size`; двоичные — только метаданные (размер, тип, для видео и картинок адрес на сайте).

## 4. Рабочая единица и долгие операции

- Рабочая единица (`work`) — папка внутри `area`, id вида `j-xxxxxxxx`, состояния `new → working → waiting_user → done | failed | cancelled`. Принадлежит хозяину аренды (персонаж); другим персонажам не видна.
- Долгая операция — это `job` по уже действующему контракту (`job.update`). Окружение шлёт `job.update` с прогрессом и итоговое событие `<окружение>.done` / `<окружение>.failed` (с `urgency`, как сейчас).
- Агент **не ждёт** операцию внутри вызова: `run` с `background` возвращает `job_id`, разговор продолжается, итог приходит событием в обычном порядке внимания.
- Отмена: `work.cancel` или `job.cancel`. Обрыв связи с ядром отменяет только работающие операции; сама рабочая область и файлы сохраняются.

## 5. Одобрения и стадии

Стадии монтажа (история, план, сборка, черновик, проверка, финал) больше не принудительный конвейер, а **навык-регламент** окружения: агент следует ему сам. Жёсткими остаются только проверки там, где ошибка дорога:

- `run` с `irreversible` и запись в выходную папку роликов — через `core.ask` (согласие пользователя) или режим приёмки окружения;
- проверка плана и кадров (`check`) — команда окружения, которую агент обязан вызвать перед финальным рендером (регламент и проверка перед `run final`);
- финальный рендер откажет без пройденной проверки (`unavailable`), так что пропустить её нельзя.

## 6. Изоляция и рабочее место

**Изоляция это сам контейнер окружения**, а не список разрешённых путей и команд. Внутри контейнера агент работает как обычный код-агент: может читать и писать любые файлы, запускать любые команды и программы, ходить в интернет и скачивать файлы. Контейнер без секретов хоста (ключи, токены, `.env` не передаются), процесс не от root, память и процессы ограничены самим контейнером, наружу выходит только то, что смонтировано (папка персонажа, том рабочих файлов, выходная папка роликов).

**Рабочее место** — набор инструментов, подготовленный заранее для удобства и надёжности, а не ограничение: навыки (`skills`), готовые команды (`run`: для монтажа приём исходников, расшифровка, озвучка, рендер, кадр, проверка, финал), единицы (`work`), ресурсы (`resources`), сайт (`site`), файлы (`files`) и произвольная оболочка (`shell`). Готовые команды быстрее и надёжнее ручных, но агент вправе обойтись и без них.

Рубежи, которые остаются:
- Всё, что выходит за контейнер (публикация ролика, сообщение людям, трата чужих ресурсов), делает ядро по согласию пользователя, а не окружение.
- Опасные для хозяина действия вне контейнера недоступны: хозяйские секреты и ФС хоста не смонтированы, монтирование папки персонажа сделано в соответствии с задачей (ресурсы на чтение, где можно).
- `final` (готовая команда) требует свежей успешной `check`; это правило регламента и готовой команды, а не запрет ручной сборки.
- Журнал действий пишет всё, что агент сделал (раздел 7а), включая `shell`.

## 7. Вход, выход и AFK

Три действия агента (прежний `workspace.switch` заменён на `workspace.enter`); модулю ядро шлёт соответствующие сообщения `workspace.enter`, `workspace.exit`, `workspace.afk` (после перезапуска ядра `workspace.resume`):

- **`workspace.enter(workspace, goal)`** — занять окружение и начать в нём работать: ядро берёт аренду, переводит фокус, запоминает причину (`user` или `self`, при самоимпульсе нужно обычное разрешение). Повторный `enter` в окружение, которое уже за ней (после AFK), возвращает в него без новой аренды (`already`).
- **`workspace.exit(workspace?)`** — выйти и **отпустить**: фокус снимается, аренда возвращается. Если в окружении остались работающие операции, отпускание ждёт их конца (аренда в состоянии `releasing`, как сейчас), новые операции начинать нельзя.
- **`workspace.afk(workspace?)`** — выйти **без отпускания**: фокус снимается, окружение остаётся за ней. Пример: пошёл долгий рендер, она отходит в другое окружение или в разговор. Операции идут, рабочая область и сайт на месте, итог приходит событием; позже `enter` возвращает её в то же окружение.
- **Фокус один**: агент работает в одном окружении, но может держать за собой несколько (в других AFK). Само ядро аренду не отпускает: только `exit` (или потеря связи, как сейчас).

Вводная приходит в ответе модуля на `enter`: `brief`, список навыков (имя и описание), открытые рабочие единицы, ссылка на сайт. Ядро кладёт её в контекст сразу после входа. Пока агент в окружении, `find_tools` показывает его инструменты первыми.

## 7а. Журнал действий (видимость работы агента)

Всё, что агент делает в окружении, видно человеку по-русски и по порядку: что читает, что пишет, что запускает, когда идёт синтез.

- Каждый вызов `skills`, `files`, `run`, `work`, `resources` окружение записывает в журнал единицы (`log.jsonl`): время, инструмент, операция, путь или команда, итог (`ok` или ошибка), короткий человеческий текст. Примеры: «Читает навык montage-regulation», «Читает work/src/Intro.tsx (3 КБ)», «Записала work/src/Intro.tsx (+42 строки)», «Озвучка: реплика vo1 «Привет…» (1 из 5)», «Рендер превью: идёт, 40 %», «Проверка плана: замечаний нет», «Отказано: запись в sources/ запрещена».
- Запись делает общий помощник SDK (`WorkspaceTools(on_action=...)`): окружение не придумывает формат, а получает готовую запись `{ts, tool, op, target, ok, error, text}`.
- Длинные команды дополнительно шлют `job.update` с текстом шага («Озвучка: 2 из 5»), чтобы ядро и дашборд видели ход.
- Сайт: вкладка «Действия» (журнал единицы, свежие сверху, обновляется сама) и строка «Сейчас» («читает work/src/Main.tsx», «ждёт ответа пользователя», «рендер 40 %») на странице единицы.
- Дашборд: в сводке окружения одна строка «Последнее действие» с временем.
- Журнал только дополняется и хранится вместе с единицей. Содержимое файлов и секреты в него не пишутся, только пути, размеры и краткий итог.

## 7б. План действий агента

План действий **живёт в самом агенте**, а не в файлах окружения: это общая функция агента, не зависящая от среды. Получив дело из нескольких шагов, агент первым делом (до входа в окружение и до любых инструментов дела) заводит задачу-план в ядре (`assistant.create_task` со `steps`), выполняет её по шагам (`assistant.task_step`) и закрывает (`assistant.close_task`). Это правило её системного промпта, окружение его не навязывает.

- Задача со шагами принадлежит дереву задач ядра (`services/tasks`): {goal, status, steps[{text, status: pending | done | skipped}], progress}. Заведённая до входа в окружение, она переносится в него при `workspace.enter` и видна через `core.tasks` этого окружения.
- Окружение только показывает план: сайт («План действий» вверху страницы единицы) и панель («Шаг n из N») читают его запросом `core.tasks` (`client.tasks()`); `job.update` единицы несёт `stage` = первый невыполненный шаг, `progress` = доля выполненных.
- Дашборд показывает текущую задачу и шаги на вкладке «Состояние» независимо от окружения (`GET /api/tasks/now`).
- Без плана на сайте пометка «агент ещё не завёл план действий».

## 7в. Что агент пишет в монтаже

Основные артефакты единицы: `plan/idea.md` (идея), `plan/story.md` (сценарий), `plan/plan.json` (монтажный лист). Остальное по необходимости: скачать ассет, проверить `ffprobe`, поправить шаблон, написать скрипт. Монтажный лист проверяет готовая команда `check` по схеме; итоговая сборка идёт командой `final`.

## 8. Сайт и панель

- У окружения свой сайт внутри него (только чтение): рабочие единицы, сценарий и план, все файлы (`hidden` скрыт), видео и кадры, кнопки внешних просмотрщиков (Remotion Studio). Запускается при входе (`enter`) и работает, пока окружение за ней, в том числе в AFK; гаснет при `exit` (отпускании аренды).
- Панель в дашборде — **только базовая информация**: название, состояние, хозяин аренды, счётчики (в работе, ждут ответа, готово), кнопки одобрения ждущих и ссылка на сайт (`panel.links` вида `url`).

## 9. Применение в других окружениях

| Окружение | Рабочая область | Команды | Навыки |
|---|---|---|---|
| Монтаж | задачи роликов; агент пишет только идею, сценарий и монтажный лист (`plan/idea.md`, `story.md`, `plan.json`), код ролика не правит, сборка по листу командами | `intake`, `transcribe`, `voiceover`, `render`, `still`, `compositions`, `check`, `final` | Remotion (справка о возможностях шаблона), регламент монтажа, дизайн «Лаборатория» |
| RimWorld | журнал колонии, заметки, настройки | команды игры (по просьбе), чтение состояния | правила колонии, словарь |
| Помощник на ПК | рабочая папка пользователя, список разрешённых программ | разрешённые приложения | справка по приложениям |

Правило: нужна новая возможность — добавь команду или навык в манифест, а не новую ветку кода агента.

## 11. Открытые вопросы

0. **Сколько окружений она держит сразу в AFK**: без предела или не больше N (память контейнеров, общая аренда монтажа). Нужен ли срок: окружение в AFK без операций долго простаивает, отпускать ли его.

1. ~~Конвейер~~ решено: стадии удалены, регламент в навыке `montage-regulation`.
2. **Одобрения**: общий режим приёмки окружения (`ask` на каждый этап) или решает ГЛаДОС по ситуации.
3. **Контекст**: навыки Remotion большие; читаются по частям (`skills` с `file`), а не целиком.
4. **Где модель**: модель одна (`pi_model`) или тяжёлая (`pi_model_heavy`) на время работы в окружении.
5. **Память**: что окружение кладёт в память персонажа после работы (итог ролика, вкусы пользователя).
