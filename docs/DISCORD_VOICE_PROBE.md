# Проба голоса Discord (DAVE)

Цель пробы: быстро и честно выяснить, получается ли у нашего бота (1) войти в голосовой канал Discord, (2) принимать РАСШИФРОВАННЫЙ звук каждого участника отдельно и (3) играть звук обратно, при том что с марта 2026 Discord требует сквозное шифрование DAVE для всех голосовых звонков. Это самый рискованный кусок будущей фичи «голосовой канал Discord».

Состояние на момент написания: проба написана и проверена только без сети (разбор аргументов, форматирование, преобразование PCM, сообщения об отсутствующих пакетах). С живым Discord её никто не запускал. Все выводы о DAVE ниже взяты из исходников и PyPI; что именно не проверено, см. раздел «Что неизвестно».

## 1. Итог исследования

Выбор:

- Основной путь: discord.py 2.7.1 (там уже есть сессия DAVE) + расширение приёма discord-ext-voice-recv + наша собственная DAVE-расшифровка через `davey`. Расширение берём только как приёмник RTP: оно снимает транспортное шифрование (PyNaCl), разводит пакеты по SSRC и сопоставляет SSRC с участником. Кадры Opus оно отдаёт «сырыми» (приёмник `wants_opus() = True`), а сквозную расшифровку делаем сами: `vc._connection.dave_session.decrypt(user_id, MediaType.audio, кадр)`, потом `discord.opus.Decoder`.
- Запасной путь: маленький Node-процесс на `@discordjs/voice` (в нём DAVE и приём в основной ветке, через тот же `davey`), отдающий ядру кадры по участникам по локальному сокету.

Почему так:

- В опубликованной версии расширения (0.5.2a179, PyPI, выложена 2025-06-18) слова DAVE нет вообще: в исходниках по `dave|davey` совпадений ноль. Без снятия DAVE все кадры Opus «декодируются» в мусор или падают с `OpusError: corrupted stream` (это описано в открытых issues расширения). Поэтому «просто поставить расширение» не работает.
- В репозитории расширения лежит минимум пять открытых PR с DAVE-расшифровкой (#54, #56, #58, #62, #65, часть с сентября-ноября 2026) и открытый issue #64 с запросом поддержки. Ни один не влит и мейнтейнер в PR #54 не отвечал. Значит, ждать релиза нельзя. Авторы PR сообщают, что работает схема «сразу после транспортной расшифровки вызвать `dave_session.decrypt` и пропустить как есть кадры без DAVE (тишина, keepalive)»; это ровно то, что делает проба, только снаружи расширения, без форка и без монкипатча его внутренностей. Только отчёты авторов PR, независимо я это не проверял.
- Свой слой расшифровки поверх публичного API расширения (приёмник-sink) переживёт обновления лучше, чем патч его `PacketDecoder`. Цена: теряем встроенный декодер, FEC и подстановку потерянных пакетов; для пробы и распознавания речи это допустимо, для продукта потом решим.

## 2. Что поставлено в образ

Правки только в `docker/core/` (образ не собирался, это сделать вам):

- `requirements.txt`:
  - `PyNaCl>=1.5,<1.6`: discord.py 2.7.1 в extra `[voice]` требует именно `<1.6` (последний PyNaCl 1.6.2 не подходит); 1.5.0 имеет готовое колесо.
  - `davey>=0.1.6,<0.2`: у 0.1.5/0.1.6/0.1.7/0.2.0 на PyPI есть готовое колесо `cp312 manylinux2014 x86_64` (Python 3.12, Linux x86_64), поэтому компилятор не нужен (есть и sdist, но он потребовал бы Rust). Версия 0.2.0 вышла 2026-11-02 и с discord.py 2.7.1 не проверялась, потому потолок `<0.2`. Ранние отчёты авторов PR работали на 0.1.6.
  - `discord-ext-voice-recv==0.5.2a179`: пре-релиз, пин точный. Чистый Python (колесо `py3-none-any`), тянет `discord.py[voice]>=2.5`.
- `Dockerfile`: `apt-get install libopus0` (в `python:slim` libopus нет; discord.py грузит её через ctypes и без неё не декодирует и не кодирует).

На самой машине разработки пакеты я скачал для проверки существования колёс и чтения исходников, но в образ не ставил и пробу с реальной библиотекой не запускал.

## 3. Как запустить пробу

Что нужно сделать вам:

1. Выдать боту права для голоса. В ссылке-приглашении сейчас `permissions=274878024768`, голосовых прав там нет. Добавляем Connect (1<<20), Speak (1<<21), Use Voice Activity (1<<25): новое число прав `274914724928`. Ссылка (подставьте ID приложения):
   `https://discord.com/oauth2/authorize?client_id=<ID_ПРИЛОЖЕНИЯ>&scope=bot&permissions=274914724928`
   (Если в вашей ссылке есть и `applications.commands`, оставьте его.) Перейти по ссылке и подтвердить на сервере: права на уже добавленного бота обновятся. Либо выдать эти права роли бота вручную на сервере или в канале.
2. Привилегированные intents для пробы не нужны (используется только `guilds` и `voice_states`, без message content и members).
3. Пересобрать образ `gits-core` (в нём теперь libopus и пакеты голоса) и запустить контейнер с токеном `DISCORD_BOT_TOKEN` в окружении (токен проба не печатает).
4. Зайти самому в голосовой канал (лучше вдвоём с кем-то ещё, ради «отдельно по участникам») и говорить.
5. Запустить в контейнере:

```
docker exec -it <контейнер> python /app/workspaces/discord/voice_probe/probe.py --guild <ID_сервера> --channel <ID_канала> --seconds 60
```

Флаг `--save` сохраняет по 5 секунд звука каждого участника в WAV 16 кГц моно в `/tmp` (по умолчанию звук нигде не сохраняется; используйте только с согласия участников и удалите файлы после прослушивания). `--save-dir` меняет каталог. ID серверов и каналов видны в Discord при включённом режиме разработчика (ПКМ, «Копировать ID»).

Заметка: пробу запускаем только на отдельном канале-песочнице, пока основной Discord-модуль не отвечает в голосе (проба открывает собственный вход бота; параллельный запуск с работающим ботом тем же токеном вытеснит одну из сессий).

## 4. Как читать результат

Раз в секунду печатается строка DAVE и по строке на участника:

```
[ 12.0с] DAVE: версия протокола=1, ready=да, статус=active
   123456789012345678: пакетов=240 расшифровано=238 сбоев=2 rms=1450
```

- версия протокола: 0 означает, что DAVE в этом канале не включён (редко); 1 и выше означает сквозное шифрование. `ready=да` значит, что сессия MLS поднята и бот ключ получил.
- пакетов: принятых кадров Opus (после транспортной расшифровки). Растёт, пока участник говорит.
- расшифровано: кадры, прошедшие DAVE и декодированные в PCM. `rms` средний уровень по ним: у тишины около 0, у речи сотни-тысячи.
- сбоев и «ошибки:»: типы ошибок (`DaveSessionNotReady`, `DecryptionFailed...`, `OpusError`, `UnknownUser`). В строке DAVE печатается последняя ошибка.
- В начале проба сама играет в канал тон 440 Гц 1 с и «фразу» из трёх нот. Её должны услышать участники (это проверка пути вывода с DAVE-шифрованием; бот свой звук не слышит).
- В конце печатается строка «ИТОГ: УСПЕХ/ЧАСТИЧНО/ПРОВАЛ».

Коды выхода: 0 нормально; 1 ошибка во время работы; 2 нет токена или неверные аргументы; 3 не хватает пакетов или libopus; 4 нет входа в Discord за 40 с; 5 канал не найден; 6 нет прав в канале.

## 5. Критерии успеха и что делать при провале

Успех (все пункты):

1. Бот вошёл в канал и не вылетел (нет закрытия соединения с кодом 4014/4017).
2. По каждому говорящему участнику «расшифровано» растёт, `rms` отличен от нуля при речи, идентификаторы разные (звук приходит отдельно по участникам).
3. С `--save` WAV каждого участника разборчив и содержит голос только этого участника.
4. Участники слышат тон и фразу бота.

Провал и действия:

- `ready=нет` и `DaveSessionNotReady` всё время: сессия DAVE не поднялась. Проверить, что `davey` реально импортируется в образе, и версию (`pip list`). Попробовать `davey==0.1.7` против 0.1.6 и наоборот. Посмотреть логи discord.py на уровне DEBUG.
- Растёт «сбоев» с `DecryptionFailed`/`UnencryptedWhenPassthroughDisabled`: частая причина, участник с камерой или демонстрацией (другие типы пакетов) либо потеря ключа после смены состава участников. В этом случае пробуем фильтровать по payload type 120 (как сделано в PR #54 расширения) и повторять расшифровку после обновления ключа.
- `UnknownUser`: SSRC не сопоставлен с участником (бот ещё не получил событие speaking). Растёт ли «расшифровано» после этого?
- Пакетов нет вообще при говорящих участниках: проверить UDP из контейнера наружу (порты Discord голос), права Connect и Use Voice Activity, что участник не в режиме «нажми и говори» без передачи.
- Не получается ни у кого, и причина в DAVE-приёме на уровне Python: переходим на запасной путь (Node-мост `@discordjs/voice`) и повторяем ту же пробу уже на нём. Это отдельная небольшая работа; сначала лучше собрать журнал ошибок основного пути, чтобы понять, баг ли это нашей схемы или версий.

## 6. Что осталось неизвестным

- Все пункты критериев успеха не проверены на живом Discord: сети и бота у меня не было.
- Совместимость `davey 0.2.0` и расширения 0.5.2a179 с discord.py 2.7.1 в реальном соединении; поэтому версии закреплены консервативно.
- Расширение вызывает `vc._get_id_from_ssrc` и `vc._connection.dave_session`: приватные API, возможны поломки при обновлении discord.py.
- Нагрузка и качество: без джиттер-буфера и FEC расширения (мы берём сырой Opus), потерянные пакеты не маскируются. Для распознавания речи может понадобиться свой буфер.
- Поведение при смене состава участников (смена эпохи MLS в середине фразы), при камерах/демонстрациях, при клиентах на Safari/iPhone (в issues расширения есть такие жалобы).
- Работает ли приём в py-cord и в основной ветке `@discordjs/voice`: только по выдаче поиска и документации, примера не запускал.

## 7. Согласие участников и политика Discord

Рекомендации (наша собственная осторожность, а не цитата правил):

- Бот должен заранее и явно объявлять в текстовом канале и голосом, что он слушает канал и что делает со звуком; входить в канал только по команде владельца или участника; выходить по просьбе любого.
- Сырой звук не хранить: держать только в памяти, пока идёт распознавание, и отбрасывать. Расшифровка речи в текст хранится по тем же правилам приватности, что и сообщения (в проекте для Discord уже есть `workspaces/discord/privacy.py`, к нему стоит привязать голос). `--save` в пробе нужен только для проверки и только с согласия присутствующих; файлы после проверки удалить.
- Запись и обработка голоса других людей без их ведома может быть незаконна (в ряде стран и штатов США нужно согласие всех участников, в ЕС голос это персональные данные). Это не юридическая консультация.

Политика Discord: текст Developer Policy и Developer Terms of Service мне прочитать не удалось (страница support-dev.discord.com отдала 403, а поиск вернул только вторичные пересказы и блоги). Поэтому не утверждаю, что именно там сказано про запись и обработку голоса и про обучение моделей на пользовательском контенте. Известно только из прессы и документации: Discord сделал DAVE обязательным для звонков с 2026-03-01, а получение звука ботами официально не документировано (в документации discord.js отдельно оговорено, что приём не гарантирован). Перед выпуском фичи нужно самим прочитать Developer Policy, Developer Terms of Service и Community Guidelines на discord.com и при необходимости раздел про обработку данных пользователей.

Источники, на которые опирался: PyPI (discord-ext-voice-recv, davey, PyNaCl, discord.py, py-cord), исходники discord.py 2.7.1, davey 0.2.0 (файл типов) и discord-ext-voice-recv 0.5.2a179, список issues/PR репозитория imayhaveborkedit/discord-ext-voice-recv (через страницу GitHub, не через API), https://daveprotocol.com/ , https://discord.com/blog/every-voice-and-video-call-on-discord-is-now-end-to-end-encrypted .

## 8. Адаптер голосового канала (продолжение пробы)

Найденное пробой повторено в рабочем адаптере `workspaces/discord/discord_voice.py` (класс `DiscordVoiceAdapter`, сессия движка голоса `discord:<guild>:<channel>`). Общая часть приёма (приёмник сырого Opus, расшифровка DAVE, декодер Opus, привязка SSRC к участнику, проверка пакетов) вынесена в `workspaces/discord/voice_rx.py`, и проба, и адаптер используют её; приватные вызовы (`_connection.dave_session`, `dave_protocol_version`, `_get_id_from_ssrc`) собраны только там. Проба остаётся рабочей (`probe.py`, её тесты проходят).

Как устроено: приём идёт в потоке расширения (расшифровка, Opus, свой потоковый ресемплер 48 кГц стерео -> 16 кГц моно на участника), дальше очередь и `send_audio` в движок; Discord не шлёт пакеты молчащим, а движок закрывает фразу по тишине, поэтому паузы после речи заполняются нулями в реальном времени (до 1,5 с). Воспроизведение: кадры движка -> 48 кГц стерео -> `discord.PCMAudio` (20 мс кадры, недогруз заполняется тишиной), `play.stop` обрывает сразу. Режимы чатов: `ignore` не пускает, `read` слушает, но играть отказывается (ack `error`: в протоколе нет причины `muted`), `reply` как обычно. Звук не пишется на диск и не логируется, только счётчики. Не проверено на живом Discord: вход, приём с DAVE, воспроизведение, джиттер и потери пакетов, смена эпохи MLS при входе и выходе участников (кадры, которые не удалось расшифровать, считаются и отбрасываются).
