# 15. Вкладки модулей в дашборде

Этап 4, отдельная небольшая задача. Репозиторий: `GitS` (плюс небольшие правки в `montage-module`, `rimworld-module`). Ветка:
`tz/15-module-tabs` от `master`. Правила исполнителя: `docs/tz/README.md`. Решение владельца (2026-10-11): у каждого модуля
своя вкладка в дашборде, **не в том же меню вкладок**, что «Состояние / Память / Модули / События»; из монтажа должна быть
ссылка на открытие ролика.

## 1. Что строим

Дашборд (`agent/static/ui/index.html`, панель справа) получает **вторую, отдельную панель выбора модуля** (ряд чипов над
содержимым, под основным рядом вкладок; в узкой панели прокручивается по горизонтали). Основные вкладки не меняются
(`Состояние`, `Память`, `Модули` как обзор, `События`, шестерёнка). Модуль выбирается чипом: при выборе основные вкладки
гаснут и показывается страница модуля; выбор основной вкладки снимает выбор модуля. Чипы есть только у подключённых или
включённых модулей (не у `planned`) и не у служб ядра (`kind: service`), порядок как в `modules.yaml`. На чипе точка
состояния (подключён / не подключён / ошибка) и бейдж числа активных задач.

## 2. Страница модуля (общая для всех модулей)

Строится из данных манифеста и реестра, код под конкретный модуль не нужен:

- **Шапка:** название, версия, состояние, кнопки «Перезапустить» и «Включён» (как в обзоре «Модули»).
- **Ссылки и действия модуля** (`panel.links`, см. 3): кнопки, открывающие ссылку в новой вкладке, или вызов инструмента
  модуля (`tool`) с показом результата.
- **Задачи модуля:** список задач этого модуля (`/api/jobs`, фильтр по модулю) с прогрессом, вопросами, отменой и
  артефактами; те же отрисовщики, что в обзоре.
- **Настройки модуля:** форма из `settings_schema`, как сейчас в обзоре.
- **Инструменты:** сворачиваемый список инструментов манифеста (имя, описание, риск, доступность).
- **События:** последние 20 событий модуля (по `module`) из журнала событий.
- **Встроенная страница** (необязательно): если модуль объявил `panel.embed_url`, она показывается в `iframe` ниже блоков.

## 3. Контракт: поле `panel` в манифесте (ТЗ 01, расширение)

Необязательный объект манифеста:

```json
"panel": {
  "title": "Монтаж",
  "icon": "film",
  "order": 40,
  "links": [
    {"id": "studio", "label": "Открыть в Remotion Studio", "kind": "tool", "tool": "montage.open_studio",
     "args_from": "job", "open_result_url": true},
    {"id": "folder", "label": "Папка роликов", "kind": "reveal_path", "path_from": "jobs_dir"},
    {"id": "docs", "label": "Документация", "kind": "url", "url": "https://..."}
  ],
  "embed_url": "http://127.0.0.1:3000"
}
```

- `kind`: `url` (открыть ссылку), `tool` (вызвать инструмент через `core.tool.call`, если результат содержит `url`, а
  `open_result_url` истинно, открыть его в новой вкладке), `reveal_path` (ядро открывает папку в проводнике, путь только из
  разрешённых каталогов модуля).
- Ссылки на артефакты задач (`job.update.artifacts`, уже есть) показываются на странице модуля и в обзоре, у файлов
  `.mp4`, `.srt`, `plan.json` кнопки «Открыть» (раздача файла ядром через `/api/artifact`, только из каталогов, которые
  модуль объявил в `panel.serve_dirs`, без выхода за пределы, без симлинков наружу; тип по расширению, `Range` для видео).
- Проверка манифеста в SDK (`protocol.py`, `validate_manifest`) знает `panel`; неверный `panel` не отклоняет модуль, а
  отбрасывается с предупреждением (модуль работает без вкладки).

## 4. Требования

- **TAB-1 (ОБЯЗАТЕЛЬНО).** SDK: поле `panel` в манифесте (разбор, проверка, тесты в SDK и `FakeCore`); реестр модулей отдаёт его в
  `/api/modules`.
- **TAB-2 (ОБЯЗАТЕЛЬНО).** Дашборд: отдельный ряд чипов модулей, вынесенный из основного ряда вкладок, страница модуля по
  разделу 2, выбор запоминается в `localStorage` (с обработкой отказа). Основные вкладки работают как раньше.
- **TAB-3 (ОБЯЗАТЕЛЬНО).** Ядро: `GET /api/artifact?module=&job=&name=` раздаёт файлы из `panel.serve_dirs`; запросы вне
  каталогов, с `..`, с симлинками наружу отклоняются; тесты на отказы. `reveal_path` через `mcp__`-независимый вызов
  ОС (`os.startfile`/`explorer`), только для каталогов из `serve_dirs`.
- **TAB-4 (ОБЯЗАТЕЛЬНО).** `montage-module`: `panel` в манифесте; инструмент `montage.open_studio` (запускает
  `npx remotion studio` рабочей копии задачи `jobs/<id>/work` с `--props=../plan/plan.json` на свободном порту, если он
  не запущен, и возвращает `url`; один Studio на задачу, останавливается с задачей или по таймауту простоя 30 минут; запуск
  объявляется через событие `montage.launch`); ссылки: «Открыть в Remotion Studio», «Папка роликов», в артефактах
  `final.mp4`, `preview.mp4`, `.srt`, `plan.json`.
- **TAB-5 (ОБЯЗАТЕЛЬНО).** `rimworld-module`: `panel` с ссылками на оверлей OBS (`http://127.0.0.1:8767/overlay`) и пульт
  оценок; больше ничего.
- **TAB-6 (ЖЕЛАТЕЛЬНО).** `telegram`, `voice`, `pet`, `desktop`: пустой `panel` с заголовком и иконкой (страница модуля по
  общему шаблону).
- **TAB-7 (ОБЯЗАТЕЛЬНО).** Проверка вручную в браузере: дашборд открывается (без ошибок в консоли), чипы не ломают узкую
  панель, ссылка открытия Studio работает против настоящего модуля монтажа (запуск Studio без рендера, объявление запуска
  слышно как факт), кнопки артефактов открывают файлы. Снимки экрана в отчёт.

## 5. Приёмка

`.\check.ps1` зелёный в затронутых репозиториях; обзор «Модули» по-прежнему работает; страница модуля монтажа показывает
задачи, настройки, инструменты и ссылки; в основном ряде вкладок новых вкладок нет; без `panel` модуль чипа не имеет, а
дашборд работает. Коммиты на английском, `Co-Authored-By`, без push, `CHANGELOG.md` в затронутых репозиториях.
