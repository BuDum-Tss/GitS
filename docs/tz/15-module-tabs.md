# 15. Подвкладки модулей в дашборде

Этап 4, отдельная небольшая задача. Репозиторий: `GitS` (плюс небольшие правки в `montage-module`, `rimworld-module`). Ветка:
`tz/15-module-tabs` от `master`. Правила исполнителя: `docs/tz/README.md`. Решение владельца (2026-10-11): у каждого модуля
своя подвкладка во вкладке «Модули» (основной ряд вкладок не меняется); из монтажа должна быть ссылка на открытие ролика.

## 1. Что строим

Решение владельца (уточнено 2026-10-11): подвкладки **внутри вкладки «Модули»**, основной ряд вкладок не растёт
(`Состояние`, `Память`, `Модули`, `События`, шестерёнка).

Во вкладке «Модули» вверху ряд подвкладок: **«Обзор»** (то, что вкладка показывает сейчас: список модулей, службы ядра,
запланированные, задачи) и по одной подвкладке на каждый подключённый или включённый модуль (не `planned`, не службы ядра
`kind: service`), порядок как в `modules.yaml`. В узкой панели ряд прокручивается по горизонтали. На подвкладке модуля
точка состояния (подключён / не подключён / ошибка) и бейдж числа активных задач. Выбранная подвкладка запоминается
(`localStorage`, с обработкой отказа); исчезнувший модуль возвращает на «Обзор».

## 2. Страница модуля: своё пространство модуля

Решение владельца: **каждый модуль сам реализует своё пространство** и показывает в нём нужную именно ему информацию.
Страница подвкладки состоит из двух частей:

1. **Общая шапка (ядро рисует сама):** название, версия, состояние, кнопки «Перезапустить» и «Включён».
2. **Пространство модуля (рисует модуль):** содержимое задаёт модуль, ядро только отображает его в стиле дашборда. Два способа,
   модуль выбирает один или оба:
   - **Блоки (по умолчанию, без своего сервера).** Модуль присылает ядру список блоков сообщением `panel.set` (контракт,
     раздел 3), ядро хранит последнее состояние модуля и отдаёт дашборду; обновление раз в 2 с как у обзора. Типы блоков:
     `stats` (подписи и значения), `table` (столбцы, строки, действия строки), `list`, `text` (простой текст, без разметки и
     HTML), `progress`, `buttons` (действия), `link`, `image`, `video`, `log` (последние строки), `tabs` (вложенные группы
     блоков). Весь текст экранируется, HTML от модуля не исполняется.
   - **Своя страница.** `panel.embed_url` (страница, которую модуль сам обслуживает на своём порту на 127.0.0.1): показывается
     в `iframe`; пригодно для богатых интерфейсов (оверлей, просмотр ролика).
3. **Служебное (сворачиваемая секция «Служебное», ядро рисует сама):** задачи модуля, настройки по `settings_schema`,
   список инструментов, последние 20 событий модуля. Раньше эти блоки были основным содержимым; теперь это запасная
   страница, которую видно сразу только у модуля, не объявившего `panel.blocks`/`embed_url`.

**Что показывает каждый модуль (минимум, реализует исполнитель в репозитории модуля):**
- `montage`: список роликов (задача, стадия, прогресс, миниатюра кадра), для готового: видео `preview.mp4`/`final.mp4`, `.srt`,
  `plan.md`, отчёт проверки качества (замечания по зонам и ремеслу), состояние режима проверки (`human`/`auto`, счётчик
  вердиктов и согласие), кнопки «Одобрить историю/план/черновик/финал», «Открыть в Remotion Studio», «Папка роликов».
- `rimworld`: состояние игры (запущена, скорость, дата, колонисты), режим агента, текущая цель и план, статус записи забега
  (файл, длительность), последние решения, оценки (пульт), ссылки на оверлей OBS.
- `telegram`: подключён ли аккаунт, очередь входящих, последние диалоги (имя, время, без текста сообщений), состояние
  отправки.
- `voice`: микрофон, STT, TTS, текущая задержка (последние замеры), состояние «слышит/говорит», выбранные устройства.
- `pet`: видим ли, текущая эмоция, позиция, запуск и скрытие.
- `desktop`: что видит экран (активное окно), состояние разрешений, задачи помощника Claude, кнопки остановки.

## 3. Контракт: поле `panel` в манифесте (ТЗ 01, расширение)

Необязательный объект манифеста:

```json
"panel": {
  "title": "Монтаж",
  "icon": "film",
  "order": 40,
  "links": [
    {"id": "studio", "label": "Открыть в Remotion Studio", "kind": "tool", "tool": "montage.open_studio",
     "args_from": "job", "open_result_url": true},
    {"id": "folder", "label": "Папка роликов", "kind": "reveal_path", "path_from": "jobs_dir"},
    {"id": "docs", "label": "Документация", "kind": "url", "url": "https://..."}
  ],
  "embed_url": "http://127.0.0.1:3000"
}
```

- `kind`: `url` (открыть ссылку), `tool` (вызвать инструмент через `core.tool.call`, если результат содержит `url`, а
  `open_result_url` истинно, открыть его в новой вкладке), `reveal_path` (ядро открывает папку в проводнике, путь только из
  разрешённых каталогов модуля).
- Ссылки на артефакты задач (`job.update.artifacts`, уже есть) показываются на странице модуля и в обзоре, у файлов
  `.mp4`, `.srt`, `plan.json` кнопки «Открыть» (раздача файла ядром через `/api/artifact`, только из каталогов, которые
  модуль объявил в `panel.serve_dirs`, без выхода за пределы, без симлинков наружу; тип по расширению, `Range` для видео).
- Сообщение модуля `panel.set` (тело `{"blocks": [...]}`, до 64 КБ, не чаще раза в секунду на модуль, лишнее отбрасывается):
  заменяет блоки модуля целиком. Ядро хранит последнее значение (в памяти) и отдаёт его `GET /api/modules/{id}/panel`.
  Действия кнопок и строк: дашборд шлёт `POST /api/modules/{id}/panel/action` `{action_id, args}`, ядро передаёт модулю запросом
  `panel.action`, модуль отвечает `{ok, message?, open_url?}`; `open_url` открывается в новой вкладке (только http/https
  на 127.0.0.1 или домены из `panel.allowed_hosts`). Объявленные в манифесте `panel.actions` (список допустимых `id`)
  проверяются, неизвестные отклоняются.
- Проверка манифеста в SDK (`protocol.py`, `validate_manifest`) знает `panel`; неверный `panel` не отклоняет модуль, а
  отбрасывается с предупреждением (модуль работает без вкладки).

## 4. Требования

- **TAB-1 (ОБЯЗАТЕЛЬНО).** SDK: поле `panel` в манифесте (разбор, проверка, тесты в SDK и `FakeCore`); реестр модулей отдаёт его в
  `/api/modules`.
- **TAB-2 (ОБЯЗАТЕЛЬНО).** Дашборд: во вкладке «Модули» ряд подвкладок («Обзор» и по одной на модуль), страница модуля по разделу 2,
  выбор запоминается. Основной ряд вкладок не меняется, «Обзор» работает как раньше.
- **TAB-3 (ОБЯЗАТЕЛЬНО).** Ядро: `GET /api/artifact?module=&job=&name=` раздаёт файлы из `panel.serve_dirs`; запросы вне
  каталогов, с `..`, с симлинками наружу отклоняются; тесты на отказы. `reveal_path` через `mcp__`-независимый вызов
  ОС (`os.startfile`/`explorer`), только для каталогов из `serve_dirs`.
- **TAB-8 (ОБЯЗАТЕЛЬНО).** SDK: `client.panel.set(blocks)`, `@client.panel_action(id)`, схема блоков и проверка (типы,
  размеры, экранирование), `FakeCore` принимает `panel.set` и шлёт `panel.action`; тесты. Ядро: хранение блоков, лимит
  частоты и размера, `GET /api/modules/{id}/panel`, `POST /api/modules/{id}/panel/action`; дашборд отрисовывает все типы
  блоков, текст через `textContent`/экранирование (тест на строку с HTML-тегами).
- **TAB-9 (ОБЯЗАТЕЛЬНО).** Пространства модулей: `montage`, `rimworld`, `telegram`, `voice`, `pet`, `desktop` присылают блоки
  по списку раздела 2 (каждый в своём репозитории, в своей ветке `tz/15-...`, по одному коммиту на модуль).
- **TAB-4 (ОБЯЗАТЕЛЬНО).** `montage-module`: `panel` в манифесте; инструмент `montage.open_studio` (запускает
  `npx remotion studio` рабочей копии задачи `jobs/<id>/work` с `--props=../plan/plan.json` на свободном порту, если он
  не запущен, и возвращает `url`; один Studio на задачу, останавливается с задачей или по таймауту простоя 30 минут; запуск
  объявляется через событие `montage.launch`); ссылки: «Открыть в Remotion Studio», «Папка роликов», в артефактах
  `final.mp4`, `preview.mp4`, `.srt`, `plan.json`.
- **TAB-5 (ОБЯЗАТЕЛЬНО).** `rimworld-module`: `panel` с ссылками на оверлей OBS (`http://127.0.0.1:8767/overlay`) и пульт
  оценок; больше ничего.
- **TAB-6 (ОБЯЗАТЕЛЬНО).** `telegram`, `voice`, `pet`, `desktop`: `panel` с заголовком, иконкой и блоками по TAB-9.
- **TAB-7 (ОБЯЗАТЕЛЬНО).** Проверка вручную в браузере: дашборд открывается (без ошибок в консоли), подвкладки не ломают узкую
  панель, ссылка открытия Studio работает против настоящего модуля монтажа (запуск Studio без рендера, объявление запуска
  слышно как факт), кнопки артефактов открывают файлы. Снимки экрана в отчёт.

## 5. Приёмка

`.\check.ps1` зелёный в затронутых репозиториях; обзор «Модули» по-прежнему работает; страница модуля монтажа показывает
свои блоки (ролики, видео, отчёт проверки, кнопки), а «Служебное» содержит задачи, настройки, инструменты и события; в основном ряде вкладок новых вкладок нет; без `panel` модуль подвкладки не имеет, а
дашборд работает. Коммиты на английском, `Co-Authored-By`, без push, `CHANGELOG.md` в затронутых репозиториях.
