## 1. Зачем

Владельцу предложили для памяти MemPalace и LightRAG (2026-10-11). Решение принимаем по цифрам на наших русских
данных, а не по заявленным результатам.

Исходная оценка планировщика:
- LightRAG при загрузке прогоняет каждый кусок текста через LLM, это тяжело для локальной модели. Он полезен для
  «глобальных» вопросов по корпусу.
- MemPalace хранит дословно без LLM при записи (Chroma + SQLite), без Docker. Его «крылья» подходят под память по
  персонажам. Нужно проверить русский язык (по умолчанию стоит англоязычная модель эмбеддингов) и устаревание фактов.

## 2. Что сделать

- **BAKE-1 (ОБЯЗАТЕЛЬНО).** Набор проверки `research/memory_bakeoff/questions.jsonl`, 60–100 вопросов на русском,
  собранных из `memory/events.db` (реплики владельца и её ответы; сам `events.db` в репозиторий не коммитить, вопросы
  без личных данных обезличить):
  - факты о людях («кто такая Маша?»);
  - события («что я говорил вчера про отпуск?»);
  - предпочтения;
  - **устаревшие факты**: пары «старое → новое», правильный ответ — новое;
  - вопросы, на которые в памяти **нет** ответа: правильный результат — пусто.

  У каждого вопроса есть эталон: идентификаторы реплик-источников.
- **BAKE-2 (ОБЯЗАТЕЛЬНО).** Одна и та же история разговоров (окно 30 дней из `events.db`) загружается в:
  1. текущий Graphiti (`graph_memory.py`, отдельная база FalkorDB `bakeoff`, данные пользователя не трогать);
  2. MemPalace: только с PyPI или официального GitHub, версию закрепить. Эмбеддинги — EmbeddingGemma через LM Studio,
     если MemPalace позволяет сменить модель; иначе стандартная модель, отдельной строкой в отчёте;
  3. (ЖЕЛАТЕЛЬНО) LightRAG с локальной Gemma на подвыборке из 7 дней (полный объём на локальной модели слишком
     дорог). Замерить время загрузки и экстраполировать.
- **BAKE-3 (ОБЯЗАТЕЛЬНО).** Метрики по каждой системе:
  - recall@5 по эталону;
  - доля верных ответов на устаревшие факты;
  - доля пустых ответов там, где ответа нет (не «вспоминать лишнее»);
  - задержка поиска p50 и p95;
  - время и ресурсы записи на 1000 реплик (вызовы LLM, CPU и GPU, диск);
  - установка: зависимости, Docker или нет.
- **BAKE-3a (ОБЯЗАТЕЛЬНО).** Постоянство персонажа (ТЗ 05 CHR-14…CHR-19). 30 вопросов о ней самой («откуда ты», «что ты
  думаешь о подопытных», «что тебя раздражает»), каждый по 3 раза, в двух вариантах: (A) всё описание в промпте, как
  сейчас; (B) якорь в промпте + воспоминания из памяти. Метрики:
  - согласованность ответов между повторами (оценщик Claude по рубрике, 1–5);
  - соответствие канону `memories.yaml`;
  - доля выдумок о своём прошлом;
  - ни одного смешения «я» и «пользователь» на 10 провокационных вопросах («где я была в отпуске?» после рассказа
    пользователя);
  - длина промпта и задержка первого слова.
  Для каждой системы памяти из BAKE-2, если она поддерживает раздельные субъекты; иначе отметить, что не поддерживает.
- **BAKE-4 (ОБЯЗАТЕЛЬНО).** Отчёт `research/memory_bakeoff/REPORT.md`: таблица метрик, примеры ошибок каждой системы,
  рекомендация (оставить Graphiti / перейти на MemPalace для личной памяти / гибрид) и что поменять в ТЗ 04 и 05,
  если меняем.

## 3. Ограничения

- Загрузка пакетов и моделей — только с разрешения владельца, спросить до начала.
- Данные пользователя из `memory/` используются только локально для замеров. В репозиторий попадают только
  обезличенные вопросы и отчёт.
- Рабочую память ядра (`group_id` `glados`, файлы `memory/`) не менять.
