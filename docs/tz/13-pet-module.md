# 13. Модуль `pet`: питомец на экране

Этап 2. Репозиторий: `GitS`. Ветка: `tz/12-13-voice-pet` — **делается одной задачей с ТЗ 12** (см. ТЗ 12).
Читать перед этим: `00-architecture.md`, `01-module-contract.md`, `02-core.md`, раздел 3 ТЗ 10 (правила модулей
монорепо), `12-voice-module.md`.

## 1. Цель

Питомец становится модулем `pet`: только показывает (стикер эмоции, облачко с текущим предложением), принимает
быстрый ввод и переключатели. Звука в питомце больше нет. Состояние приходит толчком (тема `presence`), а не опросом
`/api/state` раз в 2 секунды.

## 2. Исходное состояние (проверь)

- `desktop_pet.py` (отдельный процесс, запускает трей): окно tkinter поверх всех, стикеры `static/stickers/*.png`
  (`STICKER_MAP`), опрос `GET http://localhost:8766/api/state` (`_poll`): настройки (`voice_muted`, `volume`,
  `pet_visible`, `pet_pinned`), реплика `say` (новая по `ts` → облачко и озвучка `tts_engine.speak_sequence`),
  настроение `_mood_from` (эмоция с `EMOTION_TTL_SECS`, иначе по игровым данным `game_decision`, `pawn_fates`);
  переключение звука (`toggle_mute` → `POST /api/settings`); перетаскивание с сохранением `pet_x/pet_y`; скрытие
  (`pet_visible`); горячая клавиша быстрого ввода (`_hotkey_loop`, настройка `hotkey_input`) → `quick_input.py`
  (`POST /api/chat`, ответ через `GET /api/core`).
- `quick_input.py`, `check_stickers.py`, `static/stickers/`.

## 3. Перенос

- **PET-1 (ОБЯЗАТЕЛЬНО).** В `GitS/modules/pet/` переезжают `desktop_pet.py` (→ `main.py` + `pet_window.py`),
  `quick_input.py`, `check_stickers.py`, `static/stickers/`. Из ядра удалить; дашборд, если он отдаёт стикеры
  (проверь `static/ui`), получает путь к новой папке.
- **PET-2 (ОБЯЗАТЕЛЬНО).** Импорт `tts_engine` и вся озвучка из питомца удаляются (воспроизведение — ТЗ 12).
- **PET-3 (ОБЯЗАТЕЛЬНО).** tkinter работает в главном потоке; клиент модуля (`ModuleClient.run()`) — в отдельном
  потоке со своим циклом asyncio. Передача состояния из потока клиента в окно — через `queue.Queue` и
  `root.after(50, ...)` (как сейчас с `_input_requests`). Никаких вызовов tkinter из потока клиента.

## 4. Манифест

`id: pet`, `title: Питомец`, `capabilities: ["presence.view"]`,
`subscribe: ["presence", "settings", "module"]`,
`shared_settings: ["voice_muted", "pet_visible", "pet_pinned", "pet_x", "pet_y", "hotkey_input", "dnd",
"quiet_until"]`. Инструментов нет. Событий нет. `state: false`.

## 5. Поведение

- **PET-4 (ОБЯЗАТЕЛЬНО).** Облачко: при `presence.speaking == true` показывает `presence.segment` (текущее
  предложение, точно по событиям голоса); после конца речи облачко держится `BUBBLE_HIDE_SECS` (как сейчас) с
  последним сегментом. Если модуля голоса нет (ядро в режиме «без голоса», ТЗ 12 VOICE-15), ядро присылает
  `presence.segment` = весь текст реплики и `speaking` на оценочное время — питомец показывает как есть.
- **PET-5 (ОБЯЗАТЕЛЬНО).** Стикер: `presence.emotion`, если пришла моложе `EMOTION_TTL_SECS`; иначе `idle`; если ядро
  недоступно (клиент не подключён) — `resting`. Запасной выбор настроения по игровым данным (`game_decision`,
  `pawn_fates`) удаляется: эмоции игры приходят от `rimworld-module` через ядро (`emotion`). Это осознанное
  изменение поведения — отметить в CHANGELOG.
- **PET-6 (ОБЯЗАТЕЛЬНО).** Настройки — из `client.settings` (тема `settings`), а не из опроса. Изменения, которые
  делает сам питомец (звук вкл/выкл, позиция, видимость, закрепление), — как сейчас через `POST /api/settings`
  дашборда: UI-модули могут пользоваться HTTP-API дашборда (`/api/chat`, `/api/settings`, `/api/core`), это пульт
  управления, а не канал модуля.
- **PET-7 (ОБЯЗАТЕЛЬНО).** Быстрый ввод (`quick_input.py`) не меняется по поведению: `POST /api/chat`, ответ — как
  сейчас. Горячая клавиша — из `hotkey_input` (тема `settings`), перерегистрация при изменении.
- **PET-8 (ОБЯЗАТЕЛЬНО).** `pet_visible == false` — окно скрыто, клиент подключён (как сейчас «голос работает» — теперь
  голос и так в другом модуле).

## 6. Изменения в ядре и трее

- **PET-9 (ОБЯЗАТЕЛЬНО).** `presence` дополняется полем `emotion_ts` (время эмоции). Ядро публикует `presence` при
  каждой эмоции (`fast_brain.publish` → подписчик ядра → `hub.broadcast`).
- **PET-10 (ОБЯЗАТЕЛЬНО).** Удалить `LegacyPetSpeech`, запись `say.json` и поле `say` в `/api/state`, если им больше
  никто не пользуется (проверь `static/ui` и `quick_input`; если пользуется — оставить поле, удалить только файл
  `say.json`).
- **PET-11 (ОБЯЗАТЕЛЬНО).** `tray.py` больше не запускает питомца: `modules.yaml` получает модуль `pet`
  (`{GITS}/modules/pet`, `command: pythonw` из того же окружения — путь как `tray._pythonw()`, `args: ["main.py"]`,
  `autostart: true`, `restart: on-failure`). Пункт трея «показать/скрыть питомца» остаётся (меняет `pet_visible`).

## 7. Тесты

- **PET-12 (ОБЯЗАТЕЛЬНО).** Логика без окна выносится в чистые функции и тестируется: выбор стикера по `presence` и
  времени; текст облачка по `presence` и времени; разбор горячей клавиши (перенесённые тесты). Связка поток клиента →
  очередь → обработчик окна — тест с подменой tkinter-обработчика.

## 8. Приёмка

См. ТЗ 12 §12. Дополнительно: питомец появляется при старте ядра без трея (модуль запускает супервизор), облачко
меняется синхронно со звучащим предложением, перетаскивание и закрепление сохраняются, быстрый ввод работает.
