# Контракт модулей GitS

Файл создан скриптом `sdk/tools/gen_contract_doc.py` из `sdk/gits_sdk/contract/`. Руками не правится: меняйте описания в коде и запускайте скрипт. Тест `sdk/tests/test_contract_doc.py` сверяет файл с кодом. Руководство автора модуля: `docs/MODULES.md`, код контракта: `sdk/gits_sdk/contract/`.

Версия протокола `PROTOCOL = 1`, версия контракта `1.11`. JSON-схемы тел лежат в `docs/contract/<имя>.json`.

## Версии и совместимость

- `CONTRACT_VERSION` (мажор.минор) описывает состав контракта: минор растёт, когда появляются новые запросы, сообщения или
- необязательные поля; мажор растёт вместе с `PROTOCOL`.
- Правила:
- - добавление необязательного поля, нового запроса, сообщения или темы НЕ ломает совместимость: поднимается минор;
- - удаление, переименование, смена типа поля, превращение необязательного поля в обязательное поднимают `PROTOCOL`;
- - элемент сначала получает статус `deprecated` с датой удаления, и только после неё может быть удалён;
- - получатель игнорирует неизвестные поля и неизвестные типы сообщений (MOD-10).

## Роли и режим владения (с 1.11)

Участник шины это `workspace` (окружение: инструменты, события, рабочее место; режим владения `shared` или `owned`) или `service` (подключается к ядру по WebSocket, окружения и аренды нет; инструменты допустимы). Поля манифеста:

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `role` | string | нет | одно из `workspace`, `service`; по умолчанию `workspace` | роль участника: workspace (окружение: инструменты, события, рабочее место) или service (подключается к ядру по WebSocket, окружения и аренды нет; инструменты допустимы). Поля нет: workspace (режим совместимости) |
| `ownership` | string | нет | одно из `shared`, `owned`; по умолчанию `owned` | режим владения, только у workspace: shared (общий, эксклюзивный, берётся в аренду, см. раздел «Интерфейс управления») или owned (живёт внутри ядра персонажа) |

- `role` отсутствует: считается `workspace` (режим совместимости, прежние манифесты проходят без правок).
- `ownership` допустим только у `workspace`; у `service` манифест с этим полем отвергается.
- Поле `workspace` (описание среды агента) допустимо у `workspace` и необязательно; у `service` манифест с ним отвергается.

Рукопожатие и окружение:

- `hello` несёт `id` и `role`. Прежнее `module_id` клиент SDK шлёт рядом на время перехода; ядро принимает любое из двух (если заданы оба, они равны). `role`, если есть, совпадает с ролью манифеста.
- Адрес входа: `/ws` (новый, доступен с фазы 2) рядом с прежним `/module/ws`. Клиент SDK пока подключается к `/module/ws`.
- Переменная `GITS_ID` читается первой, `GITS_MODULE_ID` остаётся алиасом (уберёт фаза 4).
- Переменная `GITS_TOKEN` читается первой, `GITS_MODULE_TOKEN` остаётся алиасом (уберёт фаза 4).

## Запросы модуля к ядру

Модуль шлёт запрос, ядро отвечает `result`. Клиент SDK: типизированные методы `ModuleClient` (`tts`, `persona`, `llm_ask`, ...) или универсальный `request`.

### `core.ask`

Вопрос пользователю через менеджер внимания. Ответ: bool для approval, строка для choice и text.

направление: module->core, вид: request, статус: **stable**, с версии 1.0.

Коды ошибок: `bad_request`, `unavailable`, `timeout`.

Тело:

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `kind` | string | да | одно из `approval`, `choice`, `text` | вид вопроса |
| `question` | string | да | непустая | текст вопроса |
| `options` | array[string] | нет | - | варианты (для choice обязательны) |
| `timeout_s` | number | нет | от 1; до 86400; по умолчанию `300` | тайм-аут ответа, секунд |
| `context` | object | нет | - | любые данные для показа вместе с вопросом |
| `urgency_hint` | integer | нет | от 0; до 5 | подсказка срочности |

Ответ (`result.value`):

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `answer` | any | да | - | ответ пользователя (по тайм-ауту false или null) |
| `by` | string | нет | - | кто ответил (канал) |

Пример:

```json
{
  "kind": "approval",
  "question": "Запустить сборку?"
}
```

## Интерфейс управления: аренда workspace (HTTP, с 1.11)

Workspace с `ownership: shared` занимает один хозяин за раз. Хозяин (ядро персонажа) берёт окружение в аренду по HTTP, а workspace подключается к его ядру по WebSocket. Это не сообщения шины, поэтому они описаны отдельно от `Message`. Сервер: `gits_sdk.control.ControlServer`, клиент ядра: `gits_sdk.control.LeaseClient`. Авторизация: заголовок `Authorization: Bearer <GITS_CONTROL_TOKEN>` у каждого запроса. Состояния: `offline`, `free`, `busy`.

- У аренды нет срока и нет продления: она держится, пока хозяин не вызовет `release` или пока не оборвётся WebSocket участника с ядром хозяина (ядро упало или отключило участника): тогда workspace сам отпускает аренду и вызывает `on_release`.
- Один хозяин за раз; другой `character` получает 409 с описанием хозяина (без токена).
- Состояние аренды хранит сам workspace; ядро его не дублирует и читает запросом `GET /status`.
- `GET /info` описывает workspace до аренды и до подключения к ядру: для чего он и когда в него переходить (из манифеста: поле `workspace`).
- Сервер управления не стартует без токена управления (`GITS_CONTROL_TOKEN`); токен общий для всех вызывающих.
- Токен ядра хозяина из `acquire` живёт только в памяти workspace на время аренды: ни в журналы, ни в `status` он не попадает.
- Клиентская часть для ядра: `gits_sdk.control.LeaseClient(base_url, token)` с методами `status`, `info`, `acquire`, `release`.

Хозяин (`holder`):

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `character` | string | да | непустая | персонаж-хозяин |
| `core_url` | string | да | непустая | адрес ядра хозяина, к которому подключён workspace (ws:// или wss://) |
| `since` | number | да | - | когда аренда началась, unix-время в секундах |
| `purpose` | string | нет | - | зачем взято (например `play`, `montage`); пусто, если не указано |

### `GET /status`

Состояние окружения. Допустим у любого участника с интерфейсом управления: у workspace с `ownership: owned` и у service аренды нет, `state` равен `free` или `offline`, `holder` пуст, `active` считает текущие подключения.

с версии 1.11.

Ошибки (HTTP-код, тело):

- `401`: нет или неверен токен управления: `{"ok": false, "error": "unauthorized"}`

Ответ 200 (JSON):

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `id` | string | да | - | id участника |
| `role` | string | да | одно из `workspace`, `service` | роль |
| `ownership` | string | нет | одно из `shared`, `owned` | режим владения (у workspace) |
| `state` | string | да | одно из `offline`, `free`, `busy` | состояние |
| `holder` | object | да | - | хозяин аренды (поля: character, core_url, since, purpose) или null, если свободно |
| `active` | integer | да | - | сколько хозяев или подключений сейчас (для shared 0 или 1) |

Пример ответа:

```json
{
  "id": "rimworld",
  "role": "workspace",
  "ownership": "shared",
  "state": "busy",
  "holder": {
    "character": "glados",
    "core_url": "ws://127.0.0.1:8766/module/ws",
    "since": 1760000000.0,
    "purpose": "play"
  },
  "active": 1
}
```

### `GET /info`

Сведения о workspace до аренды: для чего он нужен и когда в него переходить. Источник: манифест (поле `workspace`, описания инструментов). Допустим у любого участника с интерфейсом управления; агент читает его, пока workspace не подключён к ядру.

с версии 1.11.

Ошибки (HTTP-код, тело):

- `401`: нет или неверен токен управления: `{"ok": false, "error": "unauthorized"}`

Ответ 200 (JSON):

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `id` | string | да | - | id участника |
| `role` | string | да | одно из `workspace`, `service` | роль |
| `title` | string | да | - | название |
| `purpose` | string | нет | - | для чего нужен |
| `when_to_use` | string | нет | - | когда в него переходить |
| `keywords` | array | нет | - | слова, по которым его стоит вспомнить |
| `entry` | array | нет | - | что включает среду (`user_message`, `self_impulse`, `critical`) |
| `interruptible` | boolean | нет | - | можно ли выйти в любой момент |
| `safe_points` | array | нет | - | когда выход безопасен |
| `done_when` | string | нет | - | когда дело считается законченным |
| `tools` | array | да | - | инструменты: `[{name, description}]` |
| `state` | string | да | одно из `offline`, `free`, `busy` | состояние аренды |
| `holder` | object | да | - | хозяин аренды или null |

Пример ответа:

```json
{
  "id": "montage",
  "role": "workspace",
  "title": "Монтаж",
  "purpose": "монтаж роликов",
  "when_to_use": "когда нужно смонтировать ролик из файлов",
  "keywords": [
    "монтаж",
    "ролик"
  ],
  "entry": [
    "user_message"
  ],
  "interruptible": true,
  "safe_points": [
    "между стадиями"
  ],
  "done_when": "задачи готовы",
  "tools": [
    {
      "name": "start",
      "description": "смонтировать видео"
    }
  ],
  "state": "free",
  "holder": null
}
```

### `POST /acquire`

Взять окружение в аренду. При успехе workspace вызывает обработчик `on_acquire(lease)` и подключается к ядру хозяина (`core_url`, `token` из тела). Одна аренда за раз, срока нет. Повторный запрос того же `character` с тем же `purpose` идемпотентен (тот же `lease_id`); если `core_url` или `token` изменились, прежняя аренда закрывается и открывается новая.

с версии 1.11.

Ошибки (HTTP-код, тело):

- `400`: тело неверно: `{"ok": false, "error": "bad_request", "message": ...}`
- `401`: нет или неверен токен управления: `{"ok": false, "error": "unauthorized"}`
- `404`: у этого участника нет аренды (`ownership` не `shared`)
- `409`: занято другим: `{"ok": false, "state": "busy", "holder": {...}}`
- `502`: `on_acquire` не смог подключиться: `{"ok": false, "error": "acquire_failed", "message": ...}`, аренда не выдана
- `503`: окружение недоступно: `{"ok": false, "state": "offline"}`

Тело запроса (JSON):

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `character` | string | да | непустая | персонаж-хозяин |
| `core_url` | string | да | непустая | адрес ядра хозяина |
| `token` | string | да | непустая | токен подключения к ядру хозяина (в журнал не пишется, в `holder` не отдаётся) |
| `purpose` | string | нет | - | зачем взято |

Ответ 200 (JSON):

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `ok` | boolean | да | - | true |
| `lease_id` | string | да | - | id аренды для release |

Пример запроса:

```json
{
  "character": "glados",
  "core_url": "ws://127.0.0.1:8766/module/ws",
  "token": "<токен ядра>",
  "purpose": "play"
}
```

Пример ответа:

```json
{
  "ok": true,
  "lease_id": "l-0123456789ab"
}
```

### `POST /release`

Вернуть окружение: workspace вызывает `on_release(lease)`, отключается от ядра хозяина и забывает его. Так же аренда кончается при обрыве WebSocket участника. Идемпотентно: если аренды уже нет, ответ 200 с `released: false`.

с версии 1.11.

Ошибки (HTTP-код, тело):

- `400`: тело неверно: `{"ok": false, "error": "bad_request", "message": ...}`
- `401`: нет или неверен токен управления: `{"ok": false, "error": "unauthorized"}`

Тело запроса (JSON):

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `lease_id` | string | да | непустая | id аренды |

Ответ 200 (JSON):

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `ok` | boolean | да | - | true |
| `released` | boolean | да | - | была ли аренда закрыта этим вызовом |

Пример запроса:

```json
{
  "lease_id": "l-0123456789ab"
}
```

Пример ответа:

```json
{
  "ok": true,
  "released": true
}
```

## Ресурсы персонажа

- Ресурсы персонажа лежат в `resources/<Имя>/`; папка находится по `id` в `core/character.yaml`, имя папки любое.
- Модуль читает ресурсы только из своей папки `resources/<Имя>/<id модуля>/`: `gits_sdk.resources.module_dir(<id>)`.
- Персонаж берётся из `GITS_CHARACTER_ID`, иначе `glados`; смена персонажа перезапускает модуль.
- Папка модуля не создаётся SDK и не изменяется модулем; изменяемые данные модуля лежат в `MEMORY_DIR`.
- Корень ресурсов: `GITS_RESOURCES_DIR` или `resources/` рядом с `sdk/`.
- Секреты модуль читает сам из `.env` (или `GITS_SECRETS_FILE`); в журнал и в события они не попадают.

## Что модулю запрещено

Модули (`modules/*`, кроме тестов) импортируют только стандартную библиотеку, сторонние пакеты, `gits_sdk` и свои файлы. Журнал, локальная модель, путь к Claude, опасность действия и метки трассы берутся из SDK: `client.log`, `gits_sdk.host`, `gits_sdk.claude_path`, `gits_sdk.safety`, `gits_sdk.trace`. Тест: `agent/tests/test_architecture.py`.
