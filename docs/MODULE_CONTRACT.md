# Контракт модулей GitS

Файл создан скриптом `sdk/tools/gen_contract_doc.py` из `sdk/gits_sdk/contract/`. Руками не правится: меняйте описания в коде и запускайте скрипт. Тест `sdk/tests/test_contract_doc.py` сверяет файл с кодом. Руководство автора модуля: `docs/MODULES.md`, протокол: `docs/tz/01-module-contract.md`, ТЗ контракта: `docs/tz/31-module-contracts.md`.

Версия протокола `PROTOCOL = 1`, версия контракта `1.5`. JSON-схемы тел лежат в `docs/contract/<имя>.json`.

## Версии и совместимость

- `CONTRACT_VERSION` (мажор.минор) описывает состав контракта: минор растёт, когда появляются новые запросы, сообщения или
- необязательные поля; мажор растёт вместе с `PROTOCOL`.
- Правила:
- - добавление необязательного поля, нового запроса, сообщения или темы НЕ ломает совместимость: поднимается минор;
- - удаление, переименование, смена типа поля, превращение необязательного поля в обязательное поднимают `PROTOCOL`;
- - элемент сначала получает статус `deprecated` с датой удаления, и только после неё может быть удалён;
- - получатель игнорирует неизвестные поля и неизвестные типы сообщений (MOD-10).

История:

- `1.0`: ТЗ 01, ТЗ 02, ТЗ 10, ТЗ 15, ТЗ 18: рукопожатие, события, речь, вопросы, задачи, панель, фокус, темы
- `1.1`: ТЗ 31: core.llm.ask, core.events.tail, core.claude.locate, сообщение log; типизированный клиент
- `1.2`: ТЗ 27: core.memory.episodes (эпизоды памяти ядра)
- `1.3`: core.memory.recall и core.memory.remember реализованы (были planned)
- `1.4`: ТЗ 04: core.lookup, core.experience.add, core.kb.ingest реализованы (были planned)
- `1.5`: ТЗ 32: поле манифеста workspace, запросы workspace.enter / workspace.exit / workspace.resume (policy.activate, focus.release, focus.resume остаются алиасами на один релиз)

Устаревшее: нет.

## Запросы модуля к ядру

Модуль шлёт запрос, ядро отвечает `result`. Клиент SDK: типизированные методы `ModuleClient` (`tts`, `persona`, `llm_ask`, ...) или универсальный `request`.

### `core.ask`

Вопрос пользователю через менеджер внимания. Ответ: bool для approval, строка для choice и text.

направление: module->core, вид: request, статус: **stable**, с версии 1.0.

Коды ошибок: `bad_request`, `unavailable`, `timeout`.

Тело:

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `kind` | string | да | одно из `approval`, `choice`, `text` | вид вопроса |
| `question` | string | да | непустая | текст вопроса |
| `options` | array[string] | нет | - | варианты (для choice обязательны) |
| `timeout_s` | number | нет | от 1; до 86400; по умолчанию `300` | тайм-аут ответа, секунд |
| `context` | object | нет | - | любые данные для показа вместе с вопросом |
| `urgency_hint` | integer | нет | от 0; до 5 | подсказка срочности |

Ответ (`result.value`):

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `answer` | any | да | - | ответ пользователя (по тайм-ауту false или null) |
| `by` | string | нет | - | кто ответил (канал) |

Пример:

```json
{
  "kind": "approval",
  "question": "Запустить сборку?"
}
```

### `core.kb.ingest`

Отдать документы в коллекцию базы знаний (`replace` заменяет коллекцию, `final` завершает загрузку).

направление: module->core, вид: request, статус: **stable**, с версии 1.0.

Коды ошибок: `bad_request`, `unavailable`, `denied`.

Документ: `uri`, `title`, `text`, `meta`; до 50 документов за запрос. Коллекция должна быть объявлена в `knowledge` манифеста отправителя или начинаться с его id, иначе `denied`. `replace` вместе с `final` удаляет то, чего в загрузке не было.

Тело:

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `collection` | string | да | непустая | коллекция, например montage.style |
| `documents` | array[object] | да | - | документы: объекты с текстом |
| `replace` | boolean | нет | по умолчанию `False` | заменить коллекцию целиком |
| `final` | boolean | нет | по умолчанию `False` | последняя порция |

Ответ (`result.value`):

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `stored` | integer | нет | от 0 | сколько кусков записано |
| `added` | integer | нет | от 0 | новых кусков |
| `updated` | integer | нет | от 0 | обновлено |
| `skipped` | integer | нет | от 0 | пропущено |

Пример:

```json
{
  "collection": "montage.style",
  "documents": [
    {
      "title": "Правила",
      "text": "..."
    }
  ],
  "replace": true
}
```

### `presence`

Присутствие: говорит ли она, эмоция, занятость, фокус (не чаще 10 раз в секунду).

направление: core->module, вид: topic, статус: **stable**, с версии 1.0.

Тело:

| Поле | Тип | Обязательно | Ограничения | Описание |
|---|---|---|---|---|
| `speaking` | boolean | да | - | говорит ли |
| `utterance_id` | string | нет | - | id звучащей реплики |
| `segment` | string | нет | - | звучащий фрагмент |
| `emotion` | string | да | - | эмоция |
| `emotion_ts` | number | нет | - | когда сменилась эмоция |
| `busy` | boolean | нет | - | занята ли |
| `focus` | string | нет | - | что в фокусе |
| `user_speaking` | boolean | нет | - | говорит ли человек |
| `last_user_ts` | number | нет | - | когда человек писал или говорил |
| `last_say` | string | нет | - | последняя реплика |
| `last_say_ts` | number | нет | - | когда она сказала |

Пример:

```json
{
  "speaking": false,
  "utterance_id": null,
  "segment": "",
  "emotion": "idle",
  "emotion_ts": 0.0,
  "busy": false,
  "focus": "idle",
  "user_speaking": false,
  "last_user_ts": 0.0,
  "last_say": "",
  "last_say_ts": 0.0
}
```

## Журнал ядра

Запись: `client.log(kind, text, **data)` (сообщение `log`), допустимые виды: `error`, `telegram`, `hearing`, `vision`, `approval`, `game`, `memory`.
Чтение: `core.events.tail`, допустимые виды: `game`, `telegram`, `hearing`, `vision`, `error`.

## Окружение процесса модуля

| Переменная | Кто задаёт | Обязательна | Описание | По умолчанию |
|---|---|---|---|---|
| `GITS_MODULE_TOKEN` | supervisor | да | токен шины модулей; без него SDK берёт токен из файла токена ядра | - |
| `GITS_CORE_URL` | supervisor | да | адрес шины ядра | ws://127.0.0.1:8766/module/ws |
| `GITS_MODULE_ID` | supervisor | да | id модуля из modules.yaml | - |
| `MEMORY_DIR` | supervisor | да | папка данных модуля (его память); только он пишет в неё | - |
| `GITS_CHARACTER_ID` | supervisor | да | id активного персонажа; от него зависит папка ресурсов модуля | glados |
| `PYTHONUNBUFFERED` | supervisor | нет | 1: журнал процесса без буфера | - |
| `PYTHONPATH` | supervisor | нет | пути к sdk/ и agent/ до установки пакета gits-sdk | - |
| `GITS_RESOURCES_DIR` | inherited | нет | корень ресурсов персонажей; по умолчанию resources/ рядом с sdk/ | - |
| `GITS_SECRETS_FILE` | inherited | нет | путь к secrets.env; по умолчанию agent/secrets.env | - |

## Ресурсы персонажа

- Ресурсы персонажа лежат в `resources/<Имя>/`; папка находится по `id` в `core/character.yaml`, имя папки любое.
- Модуль читает ресурсы только из своей папки `resources/<Имя>/<id модуля>/`: `gits_sdk.resources.module_dir(<id>)`.
- Персонаж берётся из `GITS_CHARACTER_ID`, иначе `glados`; смена персонажа перезапускает модуль.
- Папка модуля не создаётся SDK и не изменяется модулем; изменяемые данные модуля лежат в `MEMORY_DIR`.
- Корень ресурсов: `GITS_RESOURCES_DIR` или `resources/` рядом с `sdk/`.
- Секреты модуль читает сам из `agent/secrets.env` (или `GITS_SECRETS_FILE`); в журнал и в события они не попадают.

## Что модулю запрещено

Модули (`modules/*`, кроме тестов) импортируют только стандартную библиотеку, сторонние пакеты, `gits_sdk` и свои файлы. Журнал, локальная модель, путь к Claude, опасность действия и метки трассы берутся из SDK: `client.log`, `gits_sdk.host`, `gits_sdk.claude_path`, `gits_sdk.safety`, `gits_sdk.trace`. Тест: `agent/tests/test_architecture.py`.
