# Объявления о долгих запусках (аудит, правило 14)

Правило 14 README (решение владельца 2026-10-11): каждый долгий или заметный запуск программы или инструмента на ПК
озвучивает персонаж. Код передаёт факт «что запускается и зачем», фразу строит модель. Быстрые вспомогательные операции
(поиск, конвертация, короткий ffmpeg, внутренние процессы) не озвучиваются. Запуски подряд сливаются (AN-1).

Механизмы: флаг `announce: true` у инструмента манифеста (ядро объявляет факт перед вызовом, AN-3, `module_registry`);
`client.say(text, mode="fact", announce=True)` изнутри модуля; событие `<модуль>.launch`; из ядра `Attention.submit_announce`.

Аудит проведён 2026-10-11 по коду ветки `tz/16-announce-audit` (от master). Колонка «Объявляется» - состояние после
этой ветки; «было» отмечено там, где добавлено.

## Модуль desktop (`modules/desktop`)

| Запуск | Объявляется | Как | Почему |
|---|---|---|---|
| `launch_app`: любое приложение, в том числе RimWorld (`app_launcher` → `game_launcher.launch`) | да | флаг `announce` в манифесте | долгий запуск, до 120 с |
| `operate_screen`: цель по экрану, шаги мышью и клавиатурой | да | флаг `announce` | долгая серия действий, локальная модель шагает по экрану |
| `claude_task`: задача Claude на ПК (job) | да | флаг `announce` | долгая задача, Claude сам спрашивает разрешения на изменения |
| `take_screenshot` с `target=screen`: весь экран | да | `client.say(mode="fact", announce=True)` в `app.py` | заметно: на снимок могут попасть чужие окна |
| `take_screenshot` с `target=game` (и `focus=true`) | нет | - | быстрый снимок окна; переключение окна - короткая операция |
| `menu_click`: «Быстрый запуск», «Продолжить», «Загрузить» в RimWorld | **было нет, добавлено**: флаг `announce` | флаг `announce` (путь ядра и дашборда `POST /api/menu_click` один и тот же) | нажатие начинает или загружает партию: запуск игры |
| `focus_window`, `click`, `click_text`, `type_text`, `press_key`, `scroll`, `list_windows`, `read_screen`, `describe_screen`, `last_screenshot`, `list_apps` | нет | - | быстрые операции; `operate_screen` объявлен целиком |
| `add_app` | нет | - | только добавляет приложение в список, ничего не запускает |
| Анализ экрана (`perception`, `watch`, запрос к локальной модели зрения) | нет | - | внутренний процесс |
| PowerShell `Get-StartApps` (список приложений) | нет | - | внутренний короткий процесс |

|---|---|---|---|

## Модуль pet (`modules/pet`)

| Запуск | Объявляется | Как | Почему |
|---|---|---|---|
| Окно питомца (старт модуля) | см. раздел «Ядро» | супервизор | при автостарте ядра нет, при включении в настройках да |

## Ядро (`agent/`)

| Запуск | Объявляется | Как | Почему |
|---|---|---|---|
| Включение модуля в настройках (`Supervisor.apply`, процесс впервые) | **было нет, добавлено** | `Supervisor._announce_launch` → `Attention.submit_announce` | процесс модуля запускается по просьбе пользователя |
| Кнопка «перезапустить» (`Supervisor.restart`) | **было нет, добавлено** | то же | перезапуск модуля, правило 14 прямо его называет |
| Перезапуск процесса модуля после сбоя (`_after_exit`) | **было нет, добавлено** | то же; факт с кодом выхода и номером сбоя из пяти | модуль пропадает из работы, пользователь должен знать; пятое падение (остановка) фактом запуска не считается |
| Старт модулей при загрузке ядра (`Supervisor.start`) | нет | - | часть старта ядра: шесть фраз сразу при загрузке не нужны. **Решение, открыто владельцу** |

| Модуль без настроек (нет переменной или папки) | нет | - | он не запустится, объявлять нечего (проверка `resolve`) |
| Остановка процесса модуля (выключение, остановка ядра) | нет | - | не запуск |
| `tray.start_core` (трей запускает ядро) | нет | - | ядра ещё нет, объявить некому; запуск ядра - не запуск модуля |
| `graph_memory.ensure_model_loaded`: `lms load` (загрузка модели LM Studio для памяти-графа, до 180 с) | нет | - | внутренний процесс ядра (правило 14 исключает). **Пограничный случай:** долгий, пользователь может заметить паузу. Решение владельцу |
| `POST /api/notify` (внешние скрипты и тесты) | да (уже был, AN-2) | `dashboard.handle_api_notify` | объявление от скрипта |
| Вызов инструмента с `announce` через планировщик и через дашборд | да (уже был, AN-3) | `module_registry._make_tool` | общий путь для всех модулей |

## Расхождения с ТЗ (описаны, не исправлены)

1. **DESK-8 (`claude_task`).** ТЗ: `assistant_agent.run_task(task, context, announce)` и объявления хода задачи через
   `client.say(mode="fact")`. В коде `run_task(task, context, ask, usage)`: параметра объявлений нет, промежуточных
   объявлений нет. Объявляется только запуск (флаг `announce` у инструмента, факт «запускаю claude_task: ...»).
2. **DESK-3a (шаги `operate_screen`).** ТЗ: объявления шагов через `client.say(..., mode="fact")`. В коде шаги не
   объявляются, только запуск инструмента (флаг `announce`).
3. **DESK-3a (`take_screenshot` с `target=screen`).** ТЗ: флаг `announce: true` у инструмента. В коде объявление идёт
   через `client.say(announce=True)` внутри модуля (как записано в CHANGELOG, «Known gaps»): поведение то же, механизм другой.
4. **AN-2 (`<модуль>.launch`).** Механизм в ядре есть (`Attention.is_announce_event`), но ни один модуль в GitS не
   эмитит событие такого вида: объявления идут флагами и `say(announce=True)`.
5. **Добавлено сверх ТЗ 14, DESK-3a.** `menu_click` получил флаг `announce: true` (нажатие «Быстрый запуск», «Продолжить»,
   «Загрузить» начинает или загружает партию RimWorld). В списке ТЗ его нет; решение этого аудита, владельцу на подтверждение.

## Открытые решения владельцу

1. Старт модулей при загрузке ядра: сейчас не объявляется (только включение и перезапуски).
2. `lms load` при загрузке модели памяти-графа (до 180 с): сейчас не объявляется как внутренний процесс.
3. Публикация поста в Telegram-канал (`post`, `draft_publish`): сейчас не объявляется, т.к. не запуск на ПК.
4. Включение питомца в настройках объявляется как запуск модуля; если это лишнее, нужен отдельный признак.
