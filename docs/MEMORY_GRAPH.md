# Память-граф

Факты о людях и жизни из разговора хранятся в SQLite (файл `graph.db` в папке памяти, без Docker), всё локально: извлечение делает Gemma,
эмбеддинги EmbeddingGemma-300M, оба в LM Studio. Код: `agent/graph_memory.py` (очередь, извлечение, бэкенд `SqliteBackend`) и `agent/fact_store.py` (таблица `facts`); поиск общий, `agent/search/`. Раньше граф жил в Graphiti и FalkorDB; от них отказались ради лёгкости (решение по результатам пробы ниже и по ТЗ 04a).

## Как устроено
1. Реплика человека (чат, голос с подписью, Telegram-бот) попадает в очередь `memory/graph_queue.json` (переживает перезапуск).
   Короче 12 символов не берём; реплики ГЛаДОС не берём; незнакомые голоса не запоминаем.
2. Когда разговор не идёт (20 секунд тишины и она не говорит), Gemma одним запросом со строгой схемой выписывает устойчивые
   факты (кто, связь, что, фраза). Просьбы и мелочь дают пустой список.
3. Каждый факт пишется в таблицу `facts` (`FactStore.add`) и в гибридный индекс (слова FTS5 + вектор EmbeddingGemma). Точный повтор
   действующей связи не дублируется. У однозначных отношений (`ЖИВЁТ_В`, `РАБОТАЕТ`, `ЗОВУТ`, `ВОЗРАСТ`... список `SINGLE_VALUED`)
   новый факт закрывает прежний датой («живёт в Москве» закрывается, когда появляется «живёт в Казани»); остальные отношения
   (друг, хобби) накапливаются. Канонические факты персонажа (`canon = 1`) не закрываются.
4. Поиск: перед ответом по теме реплики берутся факты (не дольше 3 секунд), устаревшие не показываются, слабые совпадения
   отсекаются порогом косинуса 0,5. Блок попадает в контекст разговора.
5. Вкладка «Память» в дашборде: сверху пояснение, как устроены слои памяти, и счётчики по каждому; раздел «Факты» показывает сводку (действующих, устаревших, канон, очередь, размер `graph.db`), пробный поиск («что найдётся по реплике и какой блок уйдёт в подсказку») и список фактов по сущностям с фильтрами и удалением ✕ (канон не удаляется). Данные: `GET /api/graph` (с полем `stats`) и `GET /api/graph/search?q=`. Настройка «Память: факты» включает и выключает запись.
Если LM Studio или модели недоступны, граф отключается сам, очередь копится, бот работает как раньше.

## Колонисты из игры
Данные о действующих колонистах берутся из состояния игры (не из разговора) и ПЕРЕЗАПИСЫВАЮТСЯ: каждый колонист это узел, связанный с узлом-поселением (отношение КОЛОНИСТ), плюс по одному факту на навыки, черты и состояние; сама ГЛаДОС связана с поселением отношением УПРАВЛЯЕТ, у поселения есть факт СОСТАВ. Изменившийся факт заменяет прежний (без участия модели, быстро); неизменившиеся не пишутся; колонист, которого больше нет, закрывается датой и в поиске не показывается. Синхронизация идёт при смене состава и раз в пять минут.

## Эксплуатация
- База: файл `graph.db` в папке памяти ядра (рядом `graph_queue.json`), ничего поднимать не нужно. Группы (`<id>`, `<id>:<область>`)
  это колонка `group_id`, векторы и слова лежат в таблицах `docs`/`docs_fts` того же файла. Резервная копия: скопировать файл.
- Модели LM Studio загружаются сами через `lms load` (подгрузка по запросу отменяет загрузку второй модели).
- Зависимостей, кроме стандартной библиотеки и `httpx`, нет (`graphiti-core`, `falkordb`, Docker больше не нужны).

## Перенос из FalkorDB (однократно)
Пока старый контейнер графа ещё работает (`docker ps`), из папки `agent`:
```
pip install falkordb                       # нужен только для переноса
python -m tools.migrate_falkordb --dry-run # сколько связей в каких группах
python -m tools.migrate_falkordb           # перенос в $MEMORY_DIR/graph.db (по умолчанию ./memory), векторы считает LM Studio
```
Переносятся даты, канон, воспоминания персонажа и группы; повторный запуск безопасен. Потом контейнер `glados-graph` и том можно
удалить: `docker rm -f glados-graph`, `docker volume rm <проект>_graph_data`. Воспоминания персонажа можно и перезагрузить
(`python -m character seed <id>`).

## Почему извлечение наше, а не Graphiti (историческая справка: хранилище Graphiti заменено на SQLite)
Проба на 10 репликах. Полный конвейер Graphiti на Gemma 4B (4 прогона): принимает без сбоев, но теряет половину фактов
(не нашёл ни переезда, ни кота), по 80-130 секунд на реплику. Та же Gemma одной простой задачей «выпиши факты»: все факты,
4-23 секунды. Запись готовых фактов в Graphiti: 8 фактов за 85 секунд, замена «Москва → Казань» сработала, поиск по смыслу
на русском работает.

## Известные ограничения
- Объект «работает удалённо» вместо «работает дизайнером удалённо» может ошибочно закрыть прежний факт о работе (подправлено промптом).
- Старая память (`memories.json`, `memory_store`) удалена: профиль владельца теперь факты графа (столбцы
  `importance`, `profile`), планы это задачи `tasks.db`. Файл переносится один раз (`memory_migration.py`, копия `memories.json.bak`),
  переносится только важное (4-5). В графе пишутся только важные факты: о владельце и о ней 4-5, о других людях от 3.
- Скорость: ~15-30 секунд на реплику в фоне; при активном разговоре очередь копится и догоняется в паузах.
