# Маршруты событий и быстрый контур (ТЗ 25)

Код: `agent/routes.py`, правила `agent/routes/hard_rules.yaml`, ответ потоком `agent/app/reply_generator.py`, мгновенный уровень
`agent/app/instant.py`, путь обращения `agent/app/conversation_service.py`. Трасса и бюджеты: `agent/latency_trace.py`
(ТЗ 24), замеры: `docs/LATENCY_BASELINE.md`.

## 1. Вход события

Одна цепочка для всего, что приходит в ядро (событие модуля, обращение голосом, чат, Telegram):

```
вход -> нормализация и дедупликация -> жёсткие правила -> диспетчер -> routes[] -> исполнение
```

- **Нормализация и дедупликация:** `app/normalizer.py`, `app/items.py` (события), для обращения владельца - обрезка и `strip`.
- **Жёсткие правила** (без ML, до любых моделей): для событий R1-R4 (`app/process_event.py`), для обращений владельца
  `routes.hard_rules()` из YAML: «замолчи», ответ на открытый вопрос о разрешении, экстренные слова.
- **Диспетчер:** события - GLiNER и правила, Gemma только для неоднозначного (ТЗ 18, `docs/FOCUS.md` раздел 9); обращения -
  классификатор намерений (ATT-28) и `looks_like_action`.
- **`routes[]`:** список маршрутов, допустимо несколько сразу.

## 2. Маршруты

| маршрут | что это | кто исполняет |
|---|---|---|
| `reflex` | мгновенное действие без разговора: оборвать речь и генерацию, принять ответ на вопрос о разрешении, реакция D4. Итог идёт в `already_done`. | `ConversationService._reflex`, `Attention.stop_speech`, `approvals.try_answer`, фокус `reaction` |
| `chat` | ответ или реплика: локальная модель, поток предложений в речь | `ReplyGenerator.converse`, очередь речи внимания |
| `task` | поручение: планировщик, модуль фокуса, приказ в игру | `Router.handle`, `game_order`, менеджер фокуса (ТЗ 18) |
| `ignore` | ничего не говорить (сводка, отброшено) | `Digest`, `Dispatcher.act` |
| `think` | размышление (ТЗ 30) | `ReflectionService` |

Параллельные маршруты: `reflex` + `chat`. `reflex` сообщает `already_done` (факты вроде «речь остановлена по просьбе владельца»),
и маршрут `chat` получает их в контексте («Уже сделано без тебя, не повторяй и не обещай заново»). Кода с готовыми фразами нет:
передаётся факт, реплику формулирует модель.

## 3. Решения внимания на маршруты

| решение | смысл (ТЗ 03) | маршруты |
|---|---|---|
| D0 | отбросить | `ignore` |
| D1 | в сводку | `ignore` (событие остаётся в `Digest`) |
| D2 | сказать при случае (низкий приоритет) | `chat` |
| D3 | сказать | `chat` |
| D4 | срочное: сказать и сразу среагировать | `reflex` + `chat` |
| R1 | обращение владельца | `chat` (дальше путь обращения, раздел 4) |
| R2 | ответ на вопрос в канале | `reflex` |
| R3 | временное правило mute | `ignore` |
| R4 | критичное, объявленное модулем | `reflex` + `chat` |
| любое + `think_route` | напоминание себе, итог эпизода, значимое D1-D2 | к основным добавляется `think` |

Таблица - `routes.DECISION_ROUTES`, функция `routes.of_decision`. Маршруты пишутся в журнал решений (`decision`, поле `routes`) и
в запись `attention`.

## 4. Путь обращения владельца

`ConversationService.handle_text`:

1. **Жёсткие правила.** «Замолчи» (в том числе обрывок распознавания вроде «замол») и экстренное слово сразу обрывают генерацию
   ответа (`cancel_reply`) и речь, до любого вызова модели. Ответ на открытый вопрос о разрешении принимается до классификатора.
2. **Параллельно (`asyncio.gather`):** классификатор намерения, приказ в игру (`game_order`), поиск в памяти (отдельная задача с
   дедлайном), запись реплики в диалог и очередь графа (в потоке, `asyncio.to_thread`). Приказ принят - `task`, разговора нет.
3. **Маршруты** `routes.of_input`: `task`, если похоже на просьбу или классификатор сказал `action`; иначе `chat`. Если модель во
   время болтовни пометила `[ДЕЙСТВИЕ]`, добавляется `task`.
4. **Исполнение.** `chat`: поток токенов в предложения в речь. `task`: планировщик, итог говорится по факту.
5. После ответа в фоне: эмоция и отношение, осмысление беседы.

## 5. Стриминг ответа (FAST-4, FAST-5)

```
токены -> SentenceSplitter -> StreamDeclutter -> Companion.say_part -> вывод речи (speak) -> TTS
```

- Включается, если в настройке `fast_contour.stream` истина, ответ не в канал модуля, модель умеет поток (`ask_stream`) и подключён
  голос (`speech_out.supports_streaming`). Иначе прежний путь: ответ целиком, потом `say` через очередь речи.
- Маркер `[ДЕЙСТВИЕ]` разбирается до первого предложения (буфер до выяснения, маркер это или начало слова).
- `StreamDeclutter` повторяет `declutter` по целой реплике: первое предложение уходит сразу (кроме похожего на обещание действия),
  каждое следующее держится до прихода очередного, последнее проверяется на хвост-предложение помощи и третий вопрос подряд.
- Предложения идут напрямую в вывод речи (`direct`), мимо условий ожидания очереди речи внимания. Для модуля голоса первое
  предложение заменяет звучащее, остальные идут с `replace: false`, то есть встают в очередь модуля (контракт `speak`, модуль
  голоса не менялся). Не больше трёх ждущих у модуля: генерация ждёт, а не вытесняет (`BACKPRESSURE_LIVE`).
- **Отмена.** «Замолчи», экстренное слово, перебивание (`voice.user_speaking`) зовут `Companion.cancel_reply`: оборвать запрос к
  модели, остаток предложений, предложение в пути. Звучащее останавливает вывод речи. В диалог и журнал уходит то, что она успела
  сказать.
- Сбой модели до первого предложения: эскалация к Claude, как раньше. Сбой после части ответа: сказанное остаётся, Claude не зовётся.

## 6. Мгновенный уровень (FAST-3)

`InstantLevel.begin` на каждом обращении: таймер подтверждения (только `task`, `fast_contour.ack_ms`, по умолчанию 300 мс) и
таймер филлера (`filler_ms`, по умолчанию 4 с). Если к сроку настоящей реплики нет, модели уходит факт («взялась за поручение,
скажи одной фразой» или «готовишь ответ дольше обычного»), вызов идёт мимо блокировки модели (`fast_brain._ask(parallel=True)`),
чтобы не ждать план. Подтверждение отменяет объявление плана (`say_first`), филлер не сказывается после подтверждения. Эмоция и
жест «задумалась» ставятся при входе обращения. Настоящий ответ отменяет несработавшие таймеры.

## 7. Поиск в памяти с дедлайном (FAST-6)

Поиск фактов графа и воспоминаний о себе стартует вместе с классификатором и идёт параллельно в двух запросах. Дедлайн
`fast_contour.memory_deadline_ms` (300 мс) отсчитывается от старта поиска. Не успел: ответ без памяти, поиск не отменяется, и
результат кладётся в контекст следующей реплики (предзагрузка, 10 минут). Поручению (`looks_like_action`) поиск не нужен и не
запускается.

## 8. Бюджеты (FAST-8)

Настройка `latency_budget` (мс на шаг: время от предыдущей метки трассы до метки этапа; `end_to_sound` - от конца фразы до звука).
При записи трассы превышения пишутся в журнал (`budget_exceeded`, поле `stages`) и в запись `trace` (`exceeded`), в отчёте
`GET /api/latency` есть блок `budget` (сколько трасс вышло и по каким этапам). Шаги считаются по времени меток, а не по порядку
списка этапов: при стриминге первое предложение готово раньше конца ответа модели. Тесты с управляемыми часами:
`agent/tests/test_fast_contour.py`.

| этап | бюджет по умолчанию, мс |
|---|---|
| `stt_done` | 1500 |
| `core_in` | 400 |
| `classify_done` | 400 |
| `route` | 100 |
| `retrieve_done` | 450 |
| `llm_first_token` | 2500 |
| `first_sentence_ready` | 1200 |
| `llm_done` | 6000 |
| `tts_first_audio` | 1500 |
| `play_start` | 400 |
| `end_to_sound` | 4500 |

Цифры предварительные: уточнить по живым замерам (`docs/LATENCY_BASELINE.md`).

## 9. Деградация (FAST-9)

Локальная модель занята или недоступна: через `filler_ms` (и `ack_ms` на `task`) уходит факт мгновенного уровня; если модель так и
не дала ни одного предложения из-за сбоя, вопрос уходит Claude (`Companion._escalate`). Эти случаи покрыты тестами.

## 10. Добавить маршрут или правило

- Новое жёсткое правило: раздел в `agent/routes/hard_rules.yaml` и ветка в `routes.HardRules.match`; тест в `test_fast_contour.py`.
- Новый вид события: решение диспетчера уже отображено таблицей раздела 3; менять нужно только `routes.DECISION_ROUTES`.
- Новой машины состояний не добавлять: `task` исполняет менеджер фокуса (ТЗ 18, `docs/FOCUS.md`).
