# Стенд памяти: результаты (ТЗ 04a, часть без внешних сервисов)

Что это: воспроизводимый прогон `python -m tools.memory_bakeoff` (из папки `agent`) по синтетической обезличенной выборке
(`agent/tools/memory_bakeoff_data.py`: 48 записей, 45 вопросов: люди, предпочтения, события, истории из нескольких реплик,
устаревшие факты, 8 вопросов без ответа). Сравниваются варианты гибридного индекса `agent/search`.
Это НЕ полный бейкофф: Graphiti, MemPalace и LightRAG не запускались, `events.db` не использовалась.

Эмбеддер этого прогона: `hash` (детерминированный, без сети, знает только совпадения слов и пар слов), поэтому
векторная часть здесь слабее, чем будет с EmbeddingGemma: цифры вектора и гибрида занижены, а выигрыш гибрида
над FTS не показан. Прогон на EmbeddingGemma: `python -m tools.memory_bakeoff --embedder lmstudio` (нужен LM Studio),
цифры владелец добавляет сам. Порог cos для hash подобран на этой выборке (0.30 и 0.10); для EmbeddingGemma действуют
значения ТЗ 04 (0.60 и 0.45).

- Нормализация русских слов в FTS (основы вместо точных форм) даёт recall@5 0.89 уже без векторов, p95 0.2 мс.
- Замена устаревших записей (`supersedes`) обязательна: без неё верный ответ на устаревшие факты 0.0, с ней 0.8.
- Пороги работают: на вопросах без ответа гибрид отдаёт пусто в 100% случаев.
- Истории из нескольких реплик (0.75) слабее одиночных фактов: нужны эпизоды (ТЗ 27) как отдельная коллекция.
- Метрики из ТЗ 04a, которых здесь нет: время и ресурсы записи, установка, сравнение с Graphiti/MemPalace/LightRAG,
  постоянство персонажа (BAKE-3a). Решение о FalkorDB по этим цифрам принимать рано.
