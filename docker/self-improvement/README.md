# Самоисправление GitS

`core.bug_report` ставит баг в очередь из любого окружения. Поля репорта включают суть, шаги, ожидаемое и фактическое поведение. Для снимка передайте имя файла, которое вернул `desktop.take_screenshot`. Скриншот доступен Pi локально. Публичный GitHub Issue содержит текст репорта, поэтому передавайте только сведения, которые можно публиковать. `core.bug_status` по номеру заявки возвращает ссылку на Issue и итог работы.

## Запуск на Windows

Docker Desktop должен работать, а `gh auth status` должен показывать доступ к GitS. Установка берёт базовую версию из чистого коммита. Выполните из корня репозитория в PowerShell 7.

```powershell
pwsh -File docker/self-improvement/repair.ps1 -Login
pwsh -File docker/self-improvement/repair.ps1 -Install -Register
Start-ScheduledTask -TaskName 'GitS Self Improvement'
```

Для входа Pi используйте отдельные учётные данные исполнителя. Если desktop хранит снимки в другом месте, передайте абсолютный путь через `-Screenshots` при установке. `-Install` включает инструмент и пересоздаёт ядро. `-Register` настраивает запуск при входе в Windows. Для запуска вручную вызовите скрипт без флагов. `-Once` обрабатывает текущую очередь и выходит.

Хост создаёт Issues, запускает классический Pi в отдельном контейнере и проверяет патч. Коммиты сохраняются локально, а `refs/gits/repair/deployed` указывает на последнюю применённую версию. Рабочее дерево пользователя остаётся доступным для его собственных изменений. Docker проверяет готовность пересозданных сервисов. При ошибке скрипт пытается вернуть сохранённые образы. Монтаж обновляется после освобождения аренды. Итог дописывается в Issue и в файл `*.result` рядом с заявкой.

GitHub Projects можно связать с Issues автоматическим добавлением задач из репозитория. Исполнителю нужны права на Issues. Проект настраивается отдельно.
